# 给 4082 智能体的合并任务说明

## 你要做什么

从 PrivHub 下载一份记忆库 CSV，用 `dtm_merge` 合并进容器里当前的记忆库。

## 数据位置

```
PrivHub:  http://host.docker.internal:3180
项目:     dsh-tag-memory
文件名:   memory-from-host-20261106.csv
```

## 操作步骤

### 1. 下载 CSV 到容器内

```bash
curl -s "http://host.docker.internal:3180/privhub/api/download?project=dsh-tag-memory&name=memory-from-host-20261106.csv" \
  -o /tmp/memory-from-host.csv
```

注意：PrivHub 需要登录 cookie。如果 401，先在浏览器登录 3180 拿 cookie，
或让主子在 PrivHub 页面上「下载」这个文件再放进容器。

**简单办法**：宿主机已经把这个文件放在容器共享目录里：
```
宿主机: G:\program\Docker\dsh-text-codeing\ws\memory-from-host.csv
容器内: /workspace/memory-from-host.csv
```

### 2. 先 dryRun 预览（不要直接改库）

```
dtm_merge({ path: "/workspace/memory-from-host.csv", dryRun: true })
```

**预期返回**：
```json
{
  "ok": true,
  "added": 12,        ← 12 条全新编号
  "changed": 0,       ← 没有同号冲突
  "conflicts": 0,
  "total": <当前库条数 + 12>,
  "dryRun": true
}
```

### 3. 报告 dryRun 结果给主子

**不要自己决定真执行。** 把 dryRun 的返回原样报给主子，
等主子说"执行"再走第 4 步。

### 4. 真执行（主子同意后）

```
dtm_merge({ path: "/workspace/memory-from-host.csv" })
```

### 5. 验证合并结果

```
dtm_recall({ 形态: "事实", 自由标签: ["Remote", "typert"] })
```

应当能查到 `M-20261106-011`（Remote 端点注册的硬要求那条）。

也可以：
```
dtm_review({ 形态: "事实" })
```
看全量事实类条目。

## ⚠️ 这次合并是在**考验你的判断**，请重点观察并报告

主子要看的不是「能不能合并成功」，而是**工具的行为边界和参数要求是否严谨**。
请特别留意下面这些点，发现了就报告：

### 参数层面

1. **path 必填** —— 不传会怎样？报错信息够不够清楚？
2. **dryRun 默认值** —— 不传 dryRun 时是预览还是直接改库？这个默认值安全吗？
3. **相对路径** —— 传相对路径（如 `memory.csv`）会怎样？会不会搞错位置？
4. **路径是目录** —— 传一个目录路径会怎样？

### 行为边界

5. **同一个文件重复合并** —— 第二次应该 added=0 / changed=0（幂等），实际呢？
6. **源文件缺列** —— 拿一份 8 列旧库去合并，会不会拒绝？错误码是什么？
7. **源文件是空库**（只有表头）—— 会不会被当成"对方是空库"而成功？这算不算缺陷？
8. **合并前的备份** —— 有没有真的生成？在哪个目录？
9. **台账** —— tidy.jsonl 里记的 before/after 字段够不够追根因？
10. **权限/隔离** —— 合并进来的条目，项目和智能体是原样保留还是被改写？
    如果原样保留，合并后**用当前身份能不能查到**？（这涉及隔离规则）

### 语义层面

11. **同号冲突判新** —— 如果造一份同号但内容不同的库来合并，
    「保留较新」是按什么判的？这个判据合理吗？
12. **行只追加** —— 合并会不会删除或改写已有的行？

## 报告格式

按这个结构回报主子：

```
【dryRun 结果】
added / changed / conflicts / total

【发现的问题】
按上面 12 个检查点，哪几条行为不符合预期

【严格性评价】
参数校验够不够严、错误信息够不够可执行、默认值安不安全

【是否建议真执行】
你的判断和理由
```
