# 流程 · 写入（v1.0.0）

> **本文档用于指导生成和改进写入程序，不交给模型读取。**
>
> `dtm_write` 程序要做什么：收哪些字段、哪些模型给、哪些程序自己填。
> 读取见 `流程_读取.md`，整理见 `流程_整理.md`，标签含义与自由标签写法见 `标签字典.md`。
>
> **本文涉及哪些文件**：`lib/engine/write.mjs`（写入主流程）、`lib/engine/core.mjs`（读表/取号/写锁）、
> `lib/engine/tick.mjs`（时距计数，写入不碰）。记录写入 `records/write.jsonl`。

---

## 一、写入动作

模型调 dtm_write
↓
程序：要求模型提供 5 个标签值（见二）
↓
模型：提供 主要内容 / 形态 / 项目 / 智能体 / 自由标签
↓
程序：预填 4 个程序标签值（见三）
↓
程序：校验（编号是否重复、标签值是否合法、长度/数量上限）
├─ 合法 → 写入记忆库，追加一行
└─ 不合法 → 判断是模型值有问题还是程序预填值有问题
   ├─ 模型值有问题 → 报错给模型，要求更换，并列出合法值
   └─ 程序预填值有问题 → 更改为正确值，重新校验

**写入环节只追加新行，永不改写已有条目；写入环节不查重，也不做 `取代` / `归档`。**

> 这是**写入环节**的约束，不是全库铁律。读取只能改 `时距`（及据反馈更新稳定性之外的计数字段），整理可以改标签与 `状态`、并负责查重归并。
> 已弃用正文 2-gram 匹配，故写入/读取阶段不判"同一件事"；去重只在整理阶段按语义相似度处理（见《流程_整理》§四、§2.4）。

**不要绕开工具改库文件。** 不要用 write/edit/shell 重定向去动 `store/memory.csv`——绕过去就丢了编号、校验和错误提示。

## 二、模型负责填哪 5 个

| 参数 | 填什么 | 取值 / 约束 |
|---|---|---|
| `主要内容` | 要记的内容本身 | 自由文本，**无字数上限**，一条一事 |
| `形态` | 这条是哪种东西 | `技能` / `流程` / `规则` / `偏好` / `事实` / `模板` |
| `项目` | 哪个项目下的事 | `通用` / `〈项目名〉` / 外部无归属填 `引入` |
| `智能体` | 哪个身份 | `通用` / `〈身份名〉` / 外部无归属填 `引入` |
| `自由标签` | 召回主信号 | **≤ 20 个**离散词，从「作用/注意事项/内容关键词」拆 |

**这 5 个的具体含义与判据全在 `标签字典.md` 里，这里不重抄。**
自由标签的填写方向（三个拆词方向、用实词、短词优先、不写同义变体）见标签字典，程序侧只负责校验数量与去重。

程序侧要做的是：给了字典里没有的 `形态` 就拒写，并把合法值列在报错里告诉模型。

> **写入只填 5 个**，是有意收敛：领域/类型/适用阶段等信息已含在 `主要内容` 与 `自由标签` 里，读取时由 `自由标签` 交集去撞，不再单独占必填维度。少一个必填维度，就少一个判错源。

## 三、程序负责填哪 4 个

**模型不传这些，传了也忽略。它们在模型拿到参数之前就已经填好。**

### 编号
`M-YYYYMMDD-NNN`：入库当天日期 + 当天第几条，从 `001` 起。时间就在编号里，库里无单独「时间」列。
- 按**本地时间**取日期（不用 UTC，`toISOString` 跨零点会错天）
- 扫全表找当天已有最大序号，再 +1
- 序号 3 位补零

### 时距
**初始值 `1`。** 之后每被召回一次 +1（见 `流程_读取.md`）。

### 稳定性
**初始值 `观察`。** 模型不选，程序固定填 `观察`；演进见 `流程_整理.md`（观察 → 稳定 / 易变）。

### 状态
**初始值 `生效`。** 程序管，不是标签，模型看不到也不该填。

| 值 | 含义 |
|---|---|
| `生效` | 正常条目，参与召回 |
| `被取代` | 被新的一条顶掉了，读取时跳过 |
| `已归档` | 退场了，读取时跳过；**行还在，翻得回来** |

**库只追加、不删行**——归档是改状态，不是删。

## 四、库的字段（9 列，CSV）

模型填 5 + 程序填 4（存为 `store/memory.csv`，一行一条，列顺序固定）：
`编号 / 主要内容 / 形态 / 项目 / 智能体 / 自由标签 / 稳定性 / 时距 / 状态`

**落盘时的序列化规则**（细节见《架构说明》§8.1）：

- `主要内容`：含 `,` `"` 或换行 → 用 `"` 包裹，内部 `"` 写成 `""`（RFC4180）
- `自由标签`：数组用 `|` 连接成一格；读回时 `split('|')`
- `|` 是保留符，标签内容不得含它

## 五、校验规则

程序写库前逐项校验，任一不过则不写：

| 检查项 | 不过怎么办 |
|---|---|
| `主要内容` 非空 | **拒写**，报错要求模型重填 |
| `形态` 是字典合法值 | **拒写**，列合法值给模型 |
| `形态` 非空 | **拒写**（查询/写入都必填） |
| `项目` 为空 | **拒写**，列合法值要求重填（不得补默认） |
| `智能体` 为空 | **拒写**，列合法值要求重填（不得补默认） |
| `项目` / `智能体` > 40 字 | **拒写**，提示超长 |
| **`自由标签` 为空数组** | **拒写**，提示"至少给 1 个标签"（见 5.2） |
| `自由标签` 数量 > 20 | **拒写**，提示超出上限 |
| **`自由标签` 任一含 `|`** | **拒写**，指名是哪个标签、说明 `|` 是保留分隔符，要求改写后再调 |
| `自由标签` 含空串/重复 | 程序去重、滤空，不报错 |
| 编号不重复 | 程序自己重算序号（不是模型的问题） |
| 程序预填值合法 | 程序自行纠正（不是模型的问题） |

### 5.2 为什么「自由标签为空」也拒写（v1.0.0 加严）

`自由标签` 是**召回主信号**。读取时条目侧否决是 `e_ratio > 0.5`，
而 `e_ratio = |hit| / |条目标签|` —— **条目标签为空时 `e_ratio` 恒为 0，必然被否决**。

也就是说：**一条没有自由标签的记忆，除了"浏览该形态"之外永远召不回来**，等于写了个废条。
既然结果一定是废条，就该在写入时就拦住，而不是让它悄悄进库占位。

> 这是相对早期规格的**加严**（原文没写这条）。加严理由：空标签 = 100% 召不回，
> 与其让模型写了白写，不如当场告诉它"至少给一个标签"。
> **副作用**：`形态` 为空的条目仍允许存在（读取时按 §五 处理），但 `自由标签` 为空不允许。

### 5.1 保留字符的处理原则

**遇到会导致格式错乱或召回错误的字符 → 一律拒写并明确报错，让模型自己换写法。**

- 不做「程序偷偷替换」（把 `|` 换成别的）——那会静默改变模型的原意，事后查不出来。
- 报错必须**具体到哪一项、哪个字符、为什么不允许**，例如：
  `自由标签「a|b」含保留字符 |（用于分隔多个标签），请改写该标签后重试。`
- 成本很低：模型收到明确原因后改一个词即可，不需要猜。

> 当前唯一的保留字符是 `|`（`自由标签` 列的分隔符）。将来若新增保留符，同样走「拒写 + 点名」这条路。

**为什么空值「拒写」而不是「补默认通用」**：归属错了就是真的串味（项目/智能体是隔离维度），漏填一个标签不可纠正地污染隔离，所以坚决拒写、把错误告诉模型比替它猜更可靠。

**分工原则**：模型值有问题 → 报错回模型；程序预填值有问题 → 程序自己改，不打扰模型。

**未绑定会话的写入短路**：与 `功能说明 §4.3` 一致——若本次会话未绑身份，程序**直接拒写**并提示"先绑定身份"，不论模型是否显式传 `通用`/`引入`（"不知道我是谁"就不知道该把记忆归到谁的库里）。对应 `流程_读取 §一` 第 0 步。

## 六、写入记录

写入成功和失败都需要留下调取记录，为后续整理提供素材。

**存在哪**：`<dataDir>/records/write.jsonl`，**一行一条 JSON**，只追加。

记录项：

| 字段 | 例 | 说明 |
|---|---|---|
| `ts` | `2026-11-04T07:10:22+08:00` | 本地时间，ISO 格式 |
| `who` | `agent-A` | 谁写的（当前智能体） |
| `summary` | `部署时先跑 build` | `主要内容` 前 30 字 |
| `形态` / `项目` / `智能体` | `技能` / `X` / `通用` | 模型给的值 |
| `tags` | `发版检查,需先build` | 模型给的自由标签（前若干） |
| `ok` | `true` / `false` | 成功还是失败 |
| `reason` | `形态 值非法` | 失败原因（成功时省略） |
| `id` | `M-20261104-003` | 成功时的新编号（失败时省略） |

**为什么记失败**：写入失败说明「模型想记但没记成」——可能是标签判据不清（字典问题），也可能是程序校验误伤（程序问题）。整理时靠这份记录定位。

**整理怎么用**：`流程_整理.md` 第一节读这个文件，按 `ok=false` 筛出失败记录逐条判根因。
