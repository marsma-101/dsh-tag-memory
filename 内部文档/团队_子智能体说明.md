# 子智能体说明（dsh-tag-memory 开发团队）

> **总负责人 = Lead（主智能体）**：负责统一协调、接线骨架、发布归档、最终 review。
> 子智能体各管一块，**写作用域不重叠**，避免互相覆盖。

---

## 一、团队构成

| 编号 | 名称 | 负责范围 | 写作用域（互不重叠） |
|---|---|---|---|
| **L** | **Lead（总负责人）** | 阶段0 探明、package/补丁骨架、安装、PrivHub 归档、最终 review 与验收 | `package.json`、`cordis.patch.yml`、`.gitignore`、`.npmignore`、`内部文档/` |
| **E** | `engine-dev` 引擎开发者 | 纯逻辑层：CSV 读写、校验、编号、打分、闸门、隔离、时距、稳定性 | `lib/engine/**` |
| **H** | `host-dev` 宿主开发者 | 宿主入口：宿主方法、数据目录、定时任务、给 UI 与工具共用操作 | `index.js` |

## 二、各角色职责与边界

### E · engine-dev（引擎开发者）

**职责**
- `core.mjs`：**CSV 读写（RFC4180）**、路径解析、文件锁、编号 `M-YYYYMMDD-NNN`
- `write.mjs`：写入校验（9 列、6 形态、≤20 标签、`|` 保留符拒写）
- `read.mjs`：三道闸门（硬筛 → 命中否决 → 及格线）、打分（形态50/标签0~40/时距0~10）
- `tick.mjs`：时距后台累加
- `dict.mjs`：标签字典加载

**边界**
- ❌ 不碰 Cordis、不碰 `ctx`——**只接参数、返回结果**，能脱离框架单测
- ❌ 不写 `records/*.jsonl`（那是 host 的活），只返回"该写什么"给调用方
- ✅ 所有阈值从 `templates/` 或入参读，**不硬编码**

**交付判据**：`lib/engine/*` 能被 `node --test` 直接 import 测试，无需 DSH。

---

### H · host-dev（宿主开发者）

**职责**
- `index.js`：Cordis `apply(ctx, config)`
- **宿主方法**（一个操作、两个调用者）：读列表、改条目、导出、备份、恢复、合并
- 数据目录解析（4 级优先级）、`store/memory.csv` 实际落盘、`records/*.jsonl` 追加
- 定时任务（`setInterval` + `.unref()`）
- 客户端调用入口（`ctx.remote.commands.execute()` 一类，**具体写法以 Lead 阶段0 探明结论为准**）
- 会话身份投影（`ctx.sessionProjections`）

**边界**
- ❌ 不实现业务规则（打分、闸门、校验都在 engine）
- ❌ **不自建 HTTP 前缀、不自做鉴权**
- ❌ 不写 `client*.js`、不写 `preset/**`

**交付判据**：宿主方法可被 UI 与工具共同调用；CSV 正确落盘；无自建 HTTP。

---

### P · preset-dev（预设开发者）

**职责**
- Agent 预设声明（YAML 里列出本插件的子插件）
- `preset/tools.js`：10 个工具注册 `ctx.tools.register(defineTool({...}))`
  - `dtm_bind` / `dtm_write` / `dtm_recall` / `dtm_supersede` / `dtm_archive` /
    `dtm_retag` / `dtm_review` / `dtm_records` / `dtm_export` / `dtm_merge`
- **每轮提示注入** `ctx.systemPrompt.section()`：
  - 精简版标签字典 + 当前会话身份状态（未绑定/已绑定）
  - **硬约束：尽量精简，但一个 `dtm_*` 入口都不能缺**

**边界**
- ❌ 工具内部**不重复实现业务逻辑**，一律调 `lib/engine` 或宿主方法
- ❌ 不改 `index.js`、不改 `client*.js`
- ❌ 注入内容不得包含阈值推导、匹配原理、状态机细节

**交付判据**：用假 `ctx` 加载能检查到 10 个工具全部注册；注入文本通过"精简但入口齐全"检查。

---

### C · client-dev（前端开发者）

**职责**
- `client.js` 入口：模块装配、槽位注册、样式注入
- 页面：**记忆条目**（表格形态、筛选、分页、编辑）、**设置**（库位置、备份、自动整理、字典预览）
- **条目编辑**（§10.3）：只开放 `形态`/`项目`/`智能体`/`自由标签`/`稳定性`/`状态`；
  `主要内容`/`编号`/`时距` 只读
- 导出、备份/恢复/合并弹窗

**边界**
- ❌ **不 import 任何 Harness Client 包**（`dsh-client-ui-primitives` 等），控件自己写或复制宿主实现
- ❌ **不用 iframe 载入宿主 HTML**，必须是 slot 里的 React 组件
- ❌ 样式只用 `--dsw-alias-*` 主题 token
- ❌ 不写业务逻辑，只调 `client.api.js` → 宿主方法
- ❌ 不碰 `index.js`、不碰 `lib/engine`

**交付判据**：控制台无 `slot entry crashed`；明暗主题都可读；条目编辑只开放规定的 6 个字段。

---

### Q · qa（测试）

**职责**
- **只写测试、只报问题，不修业务代码**
- 引擎单测（`lib/engine`，主力）
- 工具注册冒烟（假 `ctx`，检查 10 个工具）
- 清单与语法校验（`package.json`、`cordis.patch.yml`、locale、icon、JS 语法）
- 视觉验证：有已连接页面则真验；**无浏览器控制就如实报"视觉未验证"**
- 每个里程碑按《开发流程》的测试闸门出报告

**边界**
- ❌ **不许为了通过而放宽或删除断言**——认为断言错了，只报告 + 给建议，由 Lead 定
- ❌ **不模拟 React/DOM、不伪造截图**（官方明令禁止）
- ❌ 不修业务代码；发现问题写进报告，交回对应 owner

**报告格式**：`结论（通过/不通过）` + `证据（原始输出）` + `失败项` + `没验到的部分`。

## 三、协作规则

1. **写作用域不重叠**：各人只动自己范围内文件；需要改别人范围时，**先找 Lead**。
2. **接口先行**：E 先定 `lib/engine` 的函数签名并告知 H/P；H 先定宿主方法签名并告知 C。
3. **交付即交测试**：任何人完成一块，**立即叫 Q 测**，不自测通过就宣布完成。
4. **争议上交**：设计分歧或需要改说明文件，一律报 Lead，**不擅自改 `内部文档/`**。
5. **禁止自建通道**：客户端↔宿主只走官方 Remote/命令入口；发现要走偏门先报告。
6. **不做顺手改**：旁边看到可疑点，写进报告，不动它。

## 四、边界速查（官方硬规矩，全员遵守）

| 禁止 | 原因 |
|---|---|
| 手写 profile 的 `package.json`/`cordis.patch.yml`、profile 目录跑 pnpm | 只用 `install_bundle` |
| 自建 HTTP 前缀、`connection.requestRejection` 自鉴权 | 走官方 Remote/命令入口 |
| import 任何 Harness Client 包 | 自己写控件 |
| iframe 载入宿主 HTML | 必须 slot 内 React |
| 模拟 React/DOM、伪造截图 | 验证不许造假 |
| 改动 `主要内容`/`编号`/`时距` | 一手材料与程序字段 |
| 标签含 `|` 仍写入 | 保留分隔符，必须拒写 |
