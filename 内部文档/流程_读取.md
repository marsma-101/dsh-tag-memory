# 流程 · 读取（v1.0.0）

> **本文档是指导生成读取工具用的，不直接交给模型查看。**
>
> 它说明 `dtm_recall` 程序要做什么：怎么筛、哪些必须由程序拦、怎么打分、查空怎么办。
> v1.0.0 把召回主逻辑从「描述 vs 主要内容 2-gram 匹配」改为「**query 自由标签 ∩ 条目自由标签 交集**」。
> 写入见 `流程_写入.md`，整理见 `流程_整理.md`，标签含义见 `标签字典.md`。
>
> **本文涉及哪些文件**：`lib/engine/read.mjs`（硬筛/命中否决/打分/Top-K）、`lib/engine/core.mjs`（读表）、
> `lib/engine/tick.mjs`（时距后台累加）、`lib/engine/dict.mjs`（加载精简版标签字典并注入）、
> `lib/engine/templates/tag-equivalence.json`（标签等价归一，不注入模型）。
> 记录写入 `records/read.jsonl`。

## 一、读取程序流程

**第 0 步：会话身份检查（先于一切）**
程序先查"本次会话是否已绑身份"：
- 未绑定 → **直接返回空**（不走到"智能体必填→拒查"），并在返回里标 `未绑定身份`，提示模型先 `dtm_bind`。
  （`功能说明 §4.3`"未绑定时读取返空"是绝对规则，不因模型显式传 `通用`/`引入` 而放行——不知道"我是谁"就连跨身份可见的记忆也不读，避免串身份。）
- 已绑定 → 用绑定值作为 `智能体` 硬筛值（模型也可显式覆盖）。
> 这是 `功能说明 §4.3`"未绑定时读取返空"的落地位置；模型看不到的条目它本就不该知道存在。

模型调 dtm_recall
↓
程序：要求模型提供 项目、智能体、形态、自由标签
↓
模型：给出 项目、智能体、形态（必填），自由标签（可选，≤ 20 个离散词）
↓
程序：硬筛（状态 / 项目 / 智能体）
↓
命中否决（条目侧占比 > 50%、query 侧宽松门槛；均先经等价表归一）
↓
打分（形态命中 50 + 标签交集 0~40 + 时距微加权 0~10）
↓
排序 → 取 Top-K
↓
有结果：返回候选（编号 + 主要内容摘要 + 命中解释），命中条目时距 +1
无结果：返回空，记一条 miss，时距不变

模型给出「要什么」——2 个硬筛 + 1 个强意图 + 1 组标签；**程序负责把它变成筛选、打分并返回候选**。
模型不接触库文件、不写筛选代码、不自己算匹配。它只看到返回的候选与命中解释。

## 二、两道隔离，程序必须拦死

这两道不是「建议」，是**程序层强制**——模型看不见、也拿不到的条目，它不该知道存在。

> **`P` 和 `A` 由模型在参数里给出**（`项目` / `智能体` 两个必填参数），字典里已写明它们怎么定：
> `项目` = 会话工作目录名，`智能体` = 当前身份名。程序**不再自己推断**，只按模型给的值做硬筛；
> **但要把实际用的值原样回显在返回里**，让模型能对照「我查的是哪个项目」——名字写歪时能当场发现。

### 第一道：项目隔离
当前项目名 = `P` 时，能读到的是 `项目 ∈ {通用, 引入, P}`；其余一律滤掉。

### 第二道：身份隔离
当前身份 = `A` 时，能读到的是 `智能体 ∈ {通用, 引入, A}`；其余一律滤掉。

**两道是「与」关系**，都得过。此外 `状态 ≠ 生效` 的条目一律不返回。

> `通用` 是**白名单**，不是空值：它表示「任何项目/任何身份都该知道」，所以在两道筛里都放行。

## 三、输入契约（模型提供什么）

| 参数 | 必填 | 性质 | 说明 |
|---|---|---|---|
| `项目` | 是 | 硬筛 | 当前项目名，或 `通用` / `引入` |
| `智能体` | 是 | 硬筛 | 当前身份名，或 `通用` / `引入` |
| `形态` | 是 | 加权（强意图） | 6 选 1；必须给一个，不给则拒查 |
| `自由标签` | 否 | 内容匹配 | ≤ 20 个离散词，直接给数组，不传自然语言 |

**规则**：
1. `形态` 必填——唯一强意图信号，程序靠它做主要加权。不给则拒绝查询并提示。
2. `自由标签` 是**标签数组**，不是描述文本；模型不需要知道库里存了什么词，只管组自己这边的词，等价归一由程序做。
3. 除 `形态` 外，不再要求模型给其它语义标签。
4. 模型给的 `形态` 必须是字典里的合法值；非法值拒查并列出合法值。

> 为什么只留 `形态` 一个语义必填：模型召回时最清楚的是「我要找哪种东西」；「属于哪方面」交给 `自由标签` 去撞。

## 四、打分与排序

> **本节的权重、阈值都是出厂预置值，不是精确结论。** 上线后按查空/误召回记录调整，调法见 `流程_整理.md`。调整时只动权重与阈值，不动公式结构。

### 4.1 打分公式（百分制）

对每条通过硬筛的条目：

**总分 = 形态分 + 标签分 + 时距分**（满分 100）

| 项 | 算法 | 分值 |
|---|---|---|
| 形态命中 | 条目 `形态` == 查询 `形态` | **50**，否则 0 |
| 标签交集 | 见 4.2 | 0 ~ 40（按 query 命中占比线性） |
| 时距微加权 | `min(log2(时距) × 2, 10)` | 0 ~ 10 |

**封顶原则**：标签分（≤40）不得压过形态分（50）。**形态是主信号，标签是召回主匹配信号**，比例别反。

**及格线 40 分**，见 4.3。

### 4.2 标签交集匹配（替代 2-gram）

1. 对 query 标签与条目自由标签**各自先经等价表归一**（如 `发版`≈`上线`≈`deploy`，双向）。
2. 计算交集 `hit = query标签 ∩ 条目标签`（按归一后的值）。
3. **query 命中占比** `q_ratio = |hit| / |query标签|`（描述「query 想要的有多少被这条满足」）。
4. **条目命中占比** `e_ratio = |hit| / |条目标签|`（描述「这条被 query 命中了多少」）。

标签分为 0 时不计标签分（标签分 = 0）。

> 不用 2-gram：中文「简短 vs 简洁」、中英文「部署 vs deploy」字面不重合，靠离散标签 + 等价表直接对齐，召回更稳。

### 4.3 命中否决与及格线（两步，顺序不能反）

#### 第一步：命中否决（先于分数）

```
条目侧：e_ratio > ENTRY_RATIO（出厂 0.5，即命中数 > 条目标签数 × 50%）
        否则直接淘汰（不看分数）
query 侧：q_ratio ≥ QUERY_FLOOR（出厂宽松，如 0.15）
        否则整体判为「描述方向偏」走假查空，不返回
```

**为什么必须有条目侧否决**：自由标签可能打得宽泛（一条打了 6 个标签），query 只撞 1 个无关标签就捞出来，正好是「错误召回污染上下文」。条目侧占比门槛专门堵这个洞。

> 例：条目 6 个标签、query 2 个全中 → e_ratio = 0.33 < 0.5 → **不返回**。
> 这个门槛是「宁可返空」的落地机制，阈值按实测调（见 `templates/scoring.json`）。

**query 侧门槛初值设宽松**：让宽泛无明确方向的需求多返回些参考（"需求大于参考 = 问题宽泛，多给思路"）。但太低会让乱撒网命中无关条目，所以保留一个下限。

#### 第二步：及格线 `40`

过完命中否决后，总分低于 40 仍然不返回、记 miss。

| 命中情况 | 最高分 | 过否决？ | 及格？ |
|---|---|---|---|
| 只有时距 | 10 | ❌ 不适用 | ❌ 永远不可能 |
| 只有标签（q_ratio 满、e_ratio 过） | 40 | ✅ | ⚠️ 极限才够 |
| 只有形态（标签为空） | 50 | ✅（浏览） | ✅ |
| 只有形态（标签非空但不相干） | 50 | ❌ **被否决拦住** | 不返回 |
| 形态 + 标签命中 | 50 ~ 90 | ✅ | ✅ |
| **形态不命中 + 标签满 + 时距满** | **50** | ✅ | ✅ **会返回** |

**两条结构性保证**：
1. **时距永远起不了决定作用**：单项最高 10 分，无论召回多少次都到不了 40。
2. **形态猜对不等于通行**：形态命中必须配上标签真撞上内容才返回。

> **已知放行口（有意保留，非缺陷）**：形态不命中、但标签与内容高度吻合的条目，靠 `标签40 + 时距10 = 50` 仍可过及格线。
> 这是**有意设计**——形态只是"这次想找哪类东西"的提示，标签才是内容匹配的真凭据；
> 若强行要求形态必中，会把"同一件事被误判了形态"的正确记忆永久挡在门外（形态判错本就难免）。
> 因此**保留跨形态命中**。若实测发现跨形态召回污染上下文，调高及格线或下调标签分权重即可，不改结构。

- **同分**：`编号` 新的在前，保证顺序可复现。
- **想浏览某类全部条目**：`自由标签` 留空。如「我想看看有哪些技能」→ 标签不填、形态=技能，返回该形态下全部生效条目（正当用法，不受命中否决限制）。

### 4.4 返回格式（带命中解释）

每条候选必须附命中解释：
```
[M-20261103-007] 分=78 命中：形态=技能、标签(发版检查,需先build)、e_ratio=0.67
主要内容：部署时先跑 build 再跑 test（前 60 字）
```

无命中解释的候选，模型无法判断可信度——**这是标签检索相对向量检索的优势，别浪费**。

## 五、空值怎么处理

**空值 = 这一维还没判，但不是黑名单。**
- `形态` 留空（已存条目形态为空）：照常返回，只是拿不到形态加权，靠标签和时距排序。**此处指已存条目；查询的 `形态` 必填见第三节。**
- `项目` / `智能体` 留空：理论上不该出现（写入必填、空则拒写），真出现了按 `通用` 处理，并在返回里标出来。
- **别把空值当「不匹配」滤掉**——那样空值条目会静默消失，等于白写。

## 六、`时距` 在读取里的作用

`时距` 是**程序维护的计数器**，不是筛选项，模型也不该用它来查。
- 一条记忆**被这次读取返回**时：它的 `时距` **+1**。
- **其余条目完全不动**——没被调用就不改数。
- 累加走后台队列（`lib/engine/tick.mjs`），召回时只往队列追加一行，后台慢慢消费；上一轮没做完不会叠下一轮。
- 时距在打分里只做微弱加权（**满分 10 分**），**永远单独到不了及格线**。

## 七、查空了怎么办

**必须留记录，不能静默返回空。**

**存在哪**：`<dataDir>/records/read.jsonl`，一行一条 JSON，只追加。查空和查中都要记。

| 字段 | 例 | 说明 |
|---|---|---|
| `ts` | `2026-11-04T07:10:22+08:00` | 本地时间 |
| `who` | `agent-A` | 谁查的（当前智能体） |
| `cond` | `{项目:X, 智能体:通用, 形态:技能, 标签:[发版检查]}` | 查询条件，原样不改写 |
| `total` | `128` | 查之前库里共几条 |
| `filtered` | `9` | 硬筛后剩几条 |
| `passed` | `0` | 过及格线剩几条 |
| `near` | `[M-20261020-004 分=35 e_ratio=0.40]` | **擦边条目**，最多 3 条——放宽一个维度就能命中的 |
| `hits` | `[M-20261104-003, ...]` | 实际返回的编号（查空时为空） |
| `feedback` | `[{id, verdict: ok\|wrong\|unused}]` | 命中条目的**用后反馈**（见下方）。查空时为空 |

> ⚠️ **`feedback` 的落盘方式是占位参数，待后期设计定稿。**
> 本节先把它记为 `read.jsonl` 的一个字段；但 `read.jsonl` 只追加、不做原地改写，
> 所以真正落盘时有三种候选形态（原地更新原行 / 另起一行 `action=feedback` / 只记入 `tidy.jsonl`），
> **由后续"整理与记录"专项设计一次拍板**，开发阶段不要把本节当成最终实现契约。
> 当前唯一确定的是：`feedback` 是稳定性状态机的唯一数据来源，`verdict` 取值 `ok` / `wrong` / `unused`。

**`feedback` 怎么来**：召回返回后，由**整理环节**判定该条"用对了 / 用错了 / 没用上"（同轮频繁召回错误会直接触发整理，见《流程_整理》§5.4）。它是《流程_整理》稳定性状态机的**唯一数据驱动来源**：`wrong` 累计触发降级 `易变`，连续 `ok` 触发升 `稳定`。没有它，稳定性只能人工拍板。
> **读写环节不自行改稳定性**——读写只负责记录，判定与调整都归整理。

**为什么**：查空说明「模型以为库里有、其实没有」——这是标签设计或库里真缺，不记下来就永远发现不了。整理时靠这份记录补条目、补标签、补等价表。

两类查空要区分：
- **真查空** → 库里确实没有（`filtered=0` 或 `near` 为空）。记录留着，证明那次是对的。
- **假查空** → 有但没匹配上（`near` 里就有本该命中的）。追根因：等价表缺词 → 补表；门槛过高 → 调阈值；标签方向偏 → 看是否要模型调整标签。

**`near` 是判真假的关键物证**：如果放宽一个维度就能捞到相关记忆，那次查空大概率是说明或程序的问题，不是库里真没有。

**模型侧反应（已写进注入字典）**：假查空时**按无返回正常继续，不要「换个说法再试」反复重试**——程序已记录 `near`，需要重新找时优先：留空只按形态浏览、换形态、或调整标签。继续追问只会堆词、照样查空。

## 八、Top-K 档位

`K` 默认 5，可配置。**不搞两阶段召回**——模型需要更多候选时，直接把 `K` 调大，返回格式不变。

## 九、读取动作

读取成功和失败都需要留下调取记录（格式见第七节）。
**读取本身不改内容。** 读取环节对库的写权限只有一项：`时距` 更新——那是计数，不是改记忆。
`状态`、标签、`主要内容`、`编号`、自由标签、`稳定性` 读取一律不碰（稳定性由整理环节据 `feedback` 改，见《流程_整理》§5.4）。
