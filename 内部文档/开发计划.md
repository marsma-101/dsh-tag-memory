## 阶段 2 — 写入链路（dtm_write / dtm_bind / dtm_recall）
- [x] **2.1 dtm_bind**：绑定当前会话身份（项目/智能体）。未绑定 → **写入拒写、读取返回空**（绝对规则）。
- [x] **2.2 dtm_write**：落 `store/memory.csv` + 写 `records/write.jsonl`（不查重、不做取代/归档，仅追加）。
- [x] **2.3 dtm_recall**：按评分召回（形态50 + 标签交集0~40 + 时距0~10，及格线40）；命中否决 `entry e_ratio>0.5`、`query q_ratio≥QUERY_FLOOR`；写 `records/read.jsonl` 含 `feedback{id,verdict}`。

## 阶段 3 — 整理链路（对话内，模型参与）
- [x] **3.1 触发**：对话内模型触发整理；整理身份来源 = 当前绑定 → 设置页"整理智能体" → 都没有则提问。
- [x] **3.2 去重 / 升通用**：跨身份合并同类记忆；升通用强判定（≥4 不同智能体/项目 + 语义相似>80% 且重点一致）。
- [x] **3.3 稳定性状态机**：据 `records/read.jsonl` 的 `feedback` 驱动（观察/稳定/易变）；**同轮频繁错召（召回但与需求不符）触发一次整理**去调整，不由读写环节改。`feedback` 的具体落盘形态是占位参数，待"整理与记录"专项设计定稿。
- [ ] **3.4 归纳 / 拆库拆表**：独立场合可操作化；触发（条目数超阈值 / 时距超阈值 / 自由标签重复度过高）→ 拆。（已实现：planInduction 归纳判定 + planSplit 拆库判定；三触发条件＝条目数超阈值 / 单项目占比过高 / 标签重复度过高；只在 proposals 里提议，绝不自动拆）
- [x] **3.5 写 `records/tidy.jsonl`**：动作含 `merge / feedback / user_edit`，`user_edit` 必须带项目/智能体。

## 风险与回退
- **CSV 是主选**：核心成本是 RFC4180 解析器（一次性）。若实测出现重大问题（如转义性能、误解析），回报告主，序列化层已抽出，可换其它格式。
- **未绑定铁律** 贯穿所有阶段，任何链路不得为"传通用/跨身份"放行短路。
- **稳定性** 必须由整理环节执行（程序改值、模型判断）；写入与读取一律不碰。同轮频繁错召 → 触发一次整理处理。
- **不自建通道**：客户端↔宿主一律走官方 Remote/命令入口与 storage service；发现要走偏门时先回报，不自作主张。
