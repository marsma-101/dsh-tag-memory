# 已有记忆库的检测、处置与询问规则

> 版本：v1.2.9 起生效
> 起因：包内自带初始记忆库后，必须回答一个问题——**安装时发现已有文件怎么办？**
> 「不覆盖」只是最低要求。容器里那个 0.3.7 的旧库就是反例：没被覆盖，
> 但也读不出来，用户看到的是「我的记忆全没了」。

---

## 一、为什么不能只做「不覆盖」

「不覆盖」能保住字节，但保不住**可用性**。真实出现过三种局面：

| 局面 | 不覆盖的结果 | 用户看到 |
|---|---|---|
| 库不存在 | 铺初始记忆 ✅ | 6 条说明，正常 |
| 库正常 | 跳过 ✅ | 自己的记忆，正常 |
| **库是旧格式** | 跳过 ❌ | **空列表**，以为数据丢了 |
| **库是半截文件** | 跳过 ❌ | 空列表或部分条目，无提示 |
| **两个数据目录都有库** | 只看一个 ❌ | 另一份记忆静默消失 |

所以规则必须是三段：**先检测 → 再分诊 → 该问人时问人**。

---

## 二、检测：装完先看清有什么

### 2.1 检测时机

| 时机 | 做什么 | 为什么 |
|---|---|---|
| **插件加载** | 只做**无副作用**的体检，结果缓存 | 不能因为体检失败拖住启动 |
| **首次读写** | 体检结果随返回值带出 | 这是智能体唯一能看见的通道 |
| **设置页打开** | 体检结果渲染成提示条 | 用户唯一能看见的通道 |

### 2.2 检测项（只读，绝不修改任何文件）

```
① 库文件是否存在
② 表头是否 9 列齐全            → HEADER_MISSING
③ 是否存在旧格式列名            → LEGACY_FORMAT（0.3.7 的 id/内容/时间/类型/深度/距离）
④ 行数是否 > 0                  → EMPTY_LIBRARY
⑤ 有无行列数不符 / 解析错误      → ROW_CELL_COUNT
⑥ 数据目录之外是否还有别的库     → MULTIPLE_LIBRARIES
⑦ 库文件是否可读（权限/锁）      → LIBRARY_UNREADABLE
```

### 2.3 检测结果必须给出「处置选项」

**只报错是不够的。** 报「格式不兼容」而不说能怎么办，等于把问题丢回给用户。

每个检测结果都要带一组**可执行的选项**，形如：

```js
{
  code: 'LEGACY_FORMAT',
  severity: 'blocking',            // blocking=库完全不可用 / degraded=部分可用
  found: { columns: ['id','内容',...], rows: 587, path: '/opt/dsh/tag-memory/store/memory.csv' },
  options: [
    { id: 'backup-and-fresh', label: '备份旧库，改用初始记忆库', risk: 'safe' },
    { id: 'keep-as-is',       label: '原样保留，先不动（我稍后自己处理）', risk: 'safe' },
    { id: 'manual-map',       label: '我告诉你旧列怎么对应新列', risk: 'needs-input' },
  ],
  question: '这个库是 0.3.7 的旧格式（17 列），新版是 9 列，无法自动转换。你想怎么处理？',
}
```

## 三、分诊：什么情况可以自动做，什么必须问人

这是整个规则的核心。判据只有一条：

> **会不会丢数据 / 会不会改变用户没让我改的东西？**
> 会 → 问人。不会 → 自动做，并留痕。

### 3.1 可自动执行（不丢数据、可逆）

| 情况 | 动作 | 留痕 |
|---|---|---|
| 库不存在 | 铺初始记忆库 | 日志 |
| 库存在且合法 | 什么都不做 | 无 |
| 库存在但**0 行**、表头合法 | 什么都不做（空库是合法状态） | 无 |
| 库存在但**0 行**、表头是旧格式 | 备份旧文件 → 铺初始记忆 | 备份路径 + 台账 |
| 体检失败（权限等） | 什么都不做，只报 | 日志 |

「0 行 + 旧表头」可以自动做，因为**没有数据可丢**——那正是容器里那份文件的处境。

### 3.2 必须问人（有数据、或涉及判断）

| 情况 | 为什么必须问 |
|---|---|
| 旧格式且**有数据行** | 17 列→9 列不是格式转换，是**语义重建**：类型/深度/距离 三列要合成一个「形态」，没有任何规则能推出来。猜就是编造。 |
| 两个位置都有库 | 合并顺序、谁优先，只有用户知道 |
| 库有部分坏行 | 丢掉坏行 = 删用户数据；留下 = 库一直是坏的 |
| 表头合法但内容可疑（如全部条目 项目 为空） | 可能是程序 bug 留下的，也可能是用户手改的 |

### 3.3 禁止事项（红线）

1. **不许自动迁移旧格式。** 形态无法从 类型/深度/距离 推导，自动填 = 编造用户记忆。
2. **不许自动合并两个库。** 编号可能撞车，撞了就要按「时距/稳定性」取舍——那是用户的判断。
3. **不许丢弃任何读不出来的行。** 读不出来要报出来（教训7：把读不到伪装成没有）。
4. **不许静默备份后覆盖。** 备份了也要问，因为用户可能就是要那个旧库。
5. **不许在没有用户明确同意时删除任何文件。**

## 四、怎么问：走现有通道，不加新工具

**注入预算只剩 84 字节，不能加第 11 个工具。** 询问必须搭现有通道：

### 4.1 通道一：工具返回值（给智能体看）

`dtm_recall` / `dtm_list` / `dtm_review` 的返回里已经有一个 `empty` 字段，
用来区分「真查空」和「假查空」。**扩充它**，让「库本身有问题」也走这里：

```js
{
  ok: true,
  hits: [],
  empty: 'library-broken',        // 新增值，与 true/false 并列
  libraryIssue: {                 // 新增：结构化描述
    code: 'LEGACY_FORMAT',
    severity: 'blocking',
    rows: 587,
    path: '...',
    question: '这个库是 0.3.7 的旧格式（17 列），新版是 9 列，无法自动转换。你想怎么处理？',
    options: [ ... ],
  },
  message: '库格式不兼容，一条都读不出来。不是你没有记忆。',
}
```

智能体看到 `libraryIssue` 就该：**停下来问用户**，而不是自己猜着迁移。

### 4.2 通道二：设置页提示条（给用户看）

设置页已能显示「数据目录落在包内」的警告。复用同一位置，
把 `libraryIssue` 渲染成一条带按钮的提示。

### 4.3 通道三：注入文本（给智能体立规矩）

注入里加**一句话**（必须 ≤84 字节）：

> 返回值带 `libraryIssue` 时：先问用户，别自己迁移或合并。

这句话的作用是让智能体**知道该问**，而不是硬着头皮处理。

---

## 五、智能体的行为规范

发现 `libraryIssue` 后，智能体必须按这个顺序做：

1. **停下来。** 不要继续 recall / write / 任何写操作。
2. **如实转述。** 把 `question` 和 `options` 原样告诉用户，
   不要自己加工成「你的库坏了，我帮你修」。
3. **等用户选。** 不预设答案，不推荐「最省事」的那个。
4. **执行用户选的那个。** 用户选 `keep-as-is` 就真的什么都不做。
5. **留痕。** 用 `dtm_write` 记一条「这次怎么处理的」，方便下次不再问。

**禁止智能体做的事：**
- 自己判断旧列怎么映射
- 自己决定合并还是覆盖
- 把「库读不出来」说成「你没有相关记忆」
- 在用户没回答前先备份+重建（备份不等于可以擅自改）

| 测试 | `tests/gate3/diagnose.test.mjs`（新） | 待实现 |

### 6.1 为什么体检要独立成 `diagnose.mjs`

- **纯函数、只读**：不 import fs 的写接口，从类型上保证改不了文件
- **可单测**：造几个畸形 CSV 就能验，不用起容器
- **单一职责**：`index.js` 已经 2200 行，不能再往里塞

### 6.2 与 `mergeLibrary` 的关系

**不复用，也不改它。** `mergeLibrary` 是「用户主动要求合并两个库」的工具，
有它自己的前置校验（源文件必须存在、表头必须合法）。
体检发现的是「这个库自己有问题」，性质不同，不该混进合并流程。

两者唯一的交集：用户选了「合并」选项时，智能体去调 `dtm_merge`——
但那是用户明确选择之后的事，不是体检自动触发的。

## 七、验收标准

改完必须能通过这几条实测：

1. 空目录 → 装完 6 条初始记忆
2. 正常库 → 逐字节不变
3. **0 行旧表头** → 自动备份旧文件 + 铺初始记忆，且日志说清备份到哪
4. **有数据的旧格式** → **不自动改任何东西**，返回 `libraryIssue`，且 `question` 能直接读给用户听
5. 两个目录都有库 → 返回 `MULTIPLE_LIBRARIES`，列出两个路径，不自动选
6. 注入文本 ≤ 6000 字节
7. 工具数仍是 10 个
8. 全量测试 0 失败

---

## 八、一句话总结

**能自动做的只有「没数据可丢」的那一类；只要库里有数据，
插件负责说清楚，用户负责决定，智能体负责转述——三层各司其职，谁都不越界。**
