# 待写入记忆清单（从本次对话提炼）

> 生成于 2026-11-06，用于验证「根据聊天记录存记忆 → 合并到容器」这条真实链路。
> 写入身份：智能体=阿栈，项目=dsh-tag-memory

## 一、架构决策（形态=决策/规则，稳定性=稳定）

### 1. 双标签体系是 v1.0.0 的核心变更
标签分「固定标签」和「自由标签」两类。固定标签是 6 形态 / 3 稳定性 / 3 状态，取值域锁在 schema.json；
自由标签由模型按《标签字典》自行决定，不设词表，上限 20 个，用 `|` 分隔存储。
这是相对老方案（21 列大宽表）的根本性重构，所以对外版本定 v1.0.0 而非 v0.x。

标签：双标签, 固定标签, 自由标签, v1.0.0, 架构, schema

### 2. 存储选 CSV 不选 SQLite
理由是用户要能手工编辑。Markdown 表格被否决是因为单元格不能含换行；
SQLite 被否决是因为用户打不开。最终用 RFC4180 CSV（9 列），正文里的逗号/引号/换行靠引号包裹与 `""` 转义处理。

标签：CSV, RFC4180, SQLite, Markdown, 存储格式, 决策

### 3. 召回打分只用来筛「有用」，不是「高分就返回」
形态命中 50 + 标签交集 0~40 + 时距 min(log2(t)×2, 10)。及格线 40。
但更关键的是两道否决：条目侧 e_ratio > 0.5 才通过（严格大于），query 侧 q_ratio >= 0.15。
隔离（项目/智能体）是硬筛，在打分之前就把别人的记忆挡掉——
跨智能体查不到是靠隔离，不是靠分数低。

标签：打分, e_ratio, q_ratio, 及格线, 隔离, 召回

## 二、开发过程中的缺陷教训（形态=流程/规则，稳定性=稳定）

### 4. 「把读不到伪装成没有」是本次 5 个缺陷的共同模式
① Config={} 把"配置契约不满足"伪装成"没有配置"
② bindIdentity 只返回不存储，伪装成"绑定成功"
③ recall 漏兜项目，把"筛不到"伪装成"库里没有"
④ cond 记原始 query，把"用了绑定值查"伪装成"没传条件"
⑤ 丢弃 errors，把"读不出"伪装成"空库 total:0"
共同点：错误路径返回了看起来正常的空值，调用方无法区分「真的没有」和「读不到」。

标签：缺陷模式, 静默失败, 错误处理, 教训, 空值

### 5. 假环境验业务逻辑，验不了框架契约
qa 的 177 条测试全绿，但真容器一装就炸。原因是假 ctx 绕过了 resolveConfig、模块解析、Remote 挂载。
分类结论：4 个缺陷里只有 1 个（Config={}）是真环境限制，另外 3 个本地完全能测出来，属于用例缺口。
把用例缺口说成环境限制，是最容易自我原谅的偷懒。

标签：测试, 假环境, 框架契约, 用例缺口, 教训

### 6. 必须用无头浏览器实测，不能靠推测
Remote 通道调试耗了 4 轮，每轮都是"读源码猜 API → 部署 → 用户报错 → 再猜"。
直到用 CDP 驱动无头 Edge 才一次性拿到全部真实错误。
做法：本机 Edge + --headless=new + --remote-debugging-port，自实现最小 WebSocket（约 80 行，零依赖），
能抓控制台异常、网络状态码、DOM 内容、点击交互。
不要再用「读源码推断 API」代替「跑起来看」。

标签：无头浏览器, CDP, 调试, Remote, 验证方法

### 7. 跨模块最容易漂移的不是逻辑，是字段名
筛选"是摆设"的根因：前端发 shape/project/agent/status/tags（英文），
宿主读 filter['形态']/filter['项目']（中文），读到的全是 undefined，
所有条件当"不限"，返回全量。没有任何报错。
同类：payload vs request 参数名漂移导致整个编辑功能不可用。

标签：字段名漂移, 跨模块, 契约, 筛选, 教训

## 三、工具语义（形态=规则，稳定性=稳定）

### 8. dtm_retag 的省略语义：省略 ≠ 清空
模型只传「稳定性」时，如果实现无条件把 5 个字段都塞进 patch，
其余 4 个是 undefined，宿主会当"要清空"而报 FIELD_EMPTY / TAGS_EMPTY。
正确做法：只把模型**实际给出**的字段放进 patch；undefined 跳过，但空数组/空串保留（那是真想清空）。
三层语义不能混：工具=改某几个 / UI 编辑器=整组替换 / 清空=显式传空。

标签：dtm_retag, 省略语义, patch, 工具语义, 教训

### 9. 被取代 与 已归档 互斥
被取代 = 被新条顶掉了；已归档 = 没有新顶替，只是不需要了。
两者叠在一条上会让按状态筛选时同时落两个篮子。已加 ALREADY_SUPERSEDED 拦截。

标签：被取代, 已归档, 状态互斥, 归档, 规则

### 10. dtm_merge 的同号判新要看条目状态，不能看编号
编号相同就没法用编号判新旧（比较同一字符串恒为 false，「保留较新」变死代码）。
正确判据：① 时距大者胜 ② 时距相同看稳定性 稳定>观察>易变 ③ 都一样保留当前库。
另外：合并不存在的文件必须先 stat 拦截，否则 readLibraryCsv 返回空记录会被当"空库"合并成功。

标签：dtm_merge, 合并, 判新, 时距, 稳定性, 教训

## 四、环境事实（形态=事实，稳定性=稳定）

### 11. Remote 端点注册的全部硬要求
① 不能用 ctx.typert.register({package, face, invocations}) —— 那是 lookup 注册
② 服务必须是 class 实例形态：protocol 的 remoteMethods() 只从 Object.getPrototypeOf(service) 读符号描述符
③ 方法必须同时存在于 prototype 链上，否则报 "Remote marker has no prototype method"
④ 方法签名必须是纯标识符：gateway 用 Function.toString() 解析，不许解构/默认值/rest
⑤ registerRemote 不能同步调用，要用 ctx.inject(['typert']) 延迟到 fiber 激活后
⑥ REMOTE_SIGNATURES 只能有一份定义，两份会导致"改了镜像层、marker 层没改" → 端点静默 404

标签：Remote, typert, 端点注册, marker, prototype, 硬要求

### 12. 容器与宿主机是两套独立环境
容器 dsh-text-codeing：DSH_HOME=/opt/dsh，端口 14082→4080，数据在插件包内 data/。
宿主机：DSH 跑在 C:\Users\Administrator\.dsh，profile 在 profiles/web。
两边的凭证、provider 配置、插件安装状态都独立，不能假设改一边另一边生效。

标签：容器, 宿主机, 环境, DSH, 隔离
