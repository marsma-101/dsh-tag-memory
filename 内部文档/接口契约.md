## 一、职责边界（一句话）

| 模块 | 只做 | 绝不做 |
|---|---|---|
| **engine** `lib/engine/**` | 纯逻辑 + 序列化 + 文件读写薄封装 | 不 import Cordis、不碰 `ctx`、不管身份绑定、不写日志文件（只返回"该写什么"） |
| **host** `index.js` | 调 engine、管 `ctx`、落盘调度、锁、身份投影、定时 | 不实现业务规则（打分/校验/闸门全在 engine）、不自己写 CSV 解析 |
| **preset** `preset/**` | 注册工具、注入提示；工具内部调 engine 或宿主方法 | 不重复实现业务逻辑 |

**数据流**：
```
模型 → dtm_* 工具(preset) → engine(纯逻辑) → 返回结果
                              ↑
UI → command(host) ───────────┘  （宿主方法内部同样调 engine）
```

### Q2 新增 `templates/schema.json` ✅ 批准（好主意）

## 三、engine 提的 4 个规格疑点：逐条裁决

### 疑点 1：两个「10」要拆成两个键 ✅ 完全正确
- `weights.tickMaxScore = 10` —— **打分权重上限**（`min(log2(t)×2, 10)`）
- `tickCap = 10` —— **时距字段值上限**（计数器封顶）
- 两者含义完全不同，**必须分开**，否则整理调参会误改另一个。
- 请在 `scoring.json` 里分别命名清楚，并在注释里写明区别。

### 疑点 2：`e_ratio` 的 0/0 ✅ 定为 0，被否决
- 条目标签为空、query 非空 → `e_ratio = 0` → 不满足 `> 0.5` → **否决**
- 理由：符合"宁可返空不硬凑"；空标签条目不该靠 query 捞出来
- **副作用确认**：某条标签写空后确实召不回（除非浏览模式）。
  这是**有意接受**的——标签是召回主信号，标签空了本就失去召回资格。
- 请在建契约处写明这条副作用，留痕。

### 疑点 3：浏览模式是否跳过及格线 ❌ **不需要跳过** —— 但你的担忧要单独处理

**推理**：浏览时若 query 形态 = 技能，则形态命中 = 50 分 ≥ 40，**必然过线**，不存在被滤问题。

**但你指出的真问题是另一个**：已存条目 `形态` 为空时（§五允许空值），
浏览「技能」它不匹配（不是技能），得 0 分被滤——**这是正确的**，
因为它本来就不是"技能"。§4.3 说的"该形态下全部生效条目"不包括形态为空的条目。

**所以裁决**：
- ✅ **浏览模式不跳过及格线**（保持现有规格）
- ✅ **但浏览模式（query 标签为空）跳过命中否决**（现有规格已写，保持）
- ✅ 形态为空的条目，浏览任何具体形态时都返回不到——这是设计本意，**不是缺陷**

> 形态为空的条目怎么召回？靠标签撞击（但它 e_ratio 可能为 0 被否）。
> → **补充规则**：形态为空是数据质量问题，**由整理修复**（补形态），不是读取环节的特殊照顾。
> 请在 `read.mjs` 注释里写清这个取舍。

### 疑点 4：`feedback` 是占位 ✅ 按你说的做
`buildReadLog` 里写 `feedback: []` 占位，契约注明"落盘形态待定稿"。
**不得**擅自选三种方案之一。这是主子的明确定位。

## 四、给 host-dev 的三条连带影响

engine 的决定会改变 host 的写法，**host 必须知道**：

1. **写入不是纯 append**（Q5）：必须 `withFileLock` 内完成"读表 → 取号 → 追加"
2. **CSV 解析不在 host 做**（Q3）：host 调 `core.mjs` 的 `readLibraryCsv` / `appendRecordCsv`
3. **内存态用中文键**（Q4）：宿主方法出入参都用 `record['编号']` 形态

## 六、engine 的实现顺序（已确认）

```
core(CSV) → core(编号) → core(锁) → write(校验) → write(造行)
  → read(归一/打分) → read(闸门) → read(隔离) → tick → dict
```

**每完成一项立即叫 qa 测**，不自测就宣布完成。
qa 的 `tests/**` 与 engine 的 `lib/engine/**` 不重叠，可并行。

## 七、错误码约定（engine 定义，host/preset 照用）

`CONTENT_EMPTY` `SHAPE_INVALID` `SHAPE_EMPTY` `PROJECT_EMPTY` `AGENT_EMPTY`
`NAME_TOO_LONG` `TOO_MANY_TAGS` **`TAG_CONTAINS_PIPE`**（`detail.tag` = 违规标签原文）
`HEADER_MISSING` `ROW_CELL_COUNT` `CSV_UNTERMINATED_QUOTE` `ID_DUPLICATE`
`UNBOUND_IDENTITY` `CONFIG_MISSING` `DICT_MISSING`

> `TAG_CONTAINS_PIPE` 的报错**必须点名到具体标签**（主子明确要求），
> 例：`自由标签「a|b」含保留字符 |（用于分隔多个标签），请改写该标签后重试。`
