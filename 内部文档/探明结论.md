## 1. 工具注册 `ctx.tools.register(defineTool({...}))`

**来源**：`@deepseek-ai/dsh-tools/README.md`

```ts
import { defineTool } from '@deepseek-ai/dsh-tools'

ctx.tools.register(defineTool({
  name: 'read_file',
  description: 'Read a file from disk.',
  parameters: {
    path: { type: 'string', required: true, description: 'Absolute file path' },
    offset: { type: 'number' },
    limit: { type: 'number' },
  },
  output: {
    schema: { type: 'string' },
    render: (_args, value) => [{ type: 'text', text: value }],
  },
  async execute(args, exec) {
    // args 已按 parameters 定型；exec.signal 用于取消
    return readFile(args.path, { encoding: 'utf8', signal: exec.signal })
  },
}))
```

**要点**
- `parameters` 是统一 schema DSL：`string` / `number` / `integer` / `boolean` / `null` / `array` / `object` / `json` / `oneOf`
- 每个参数是对象，`required: true` 标必填，`description` 给模型看
- `output.schema` 声明返回类型；`output.render` 决定模型看到什么
- `execute(args, exec)` 返回**只含声明过的 JSON 值**；`exec.signal` 用于超时/取消
- **参数在校验后才执行**，非法输入变成普通错误结果（不中断轮次）
- 注册即模型可见——registry 自动把 schema 喂给 system-prompt assembly

**对本插件的意义**：`dtm_retag` 的 `basis` 必填可以直接用 `required: true` 表达；标签含 `|` 的拒写放在 `execute` 里抛错。

## 2. 系统提示注入 `ctx.systemPrompt.section(...)`

**来源**：`@deepseek-ai/dsh-system-prompt/README.md`

```text
ctx.systemPrompt.section({
  name: 'tool:bash',
  order: 100,
  text: 'Prefer bash for file and process operations.',
})
```

**要点**
- `name` 唯一标识、`order` 排序、`text` 是注入内容
- `interpolate: false` 可保留 `{{...}}` 字面（我们注入的字典里有花括号时必须设，否则会被当变量解析失败）
- 变量：`ctx.systemPrompt.variable('name', () => 'value')`，文本里用 `{{name}}` 引用
- **agent 作用域优先**：通过 `agent.ctx` 注册只影响该 agent
- 同一个 name 重复注册会被覆盖（不是并列）

**对本插件的意义**：`标签字典.md` + 身份状态用一次 `section()` 注入；
**内容里有 `{{` 时必须 `interpolate: false`**，否则 assembly 会因未解析变量而失败。

## 3. 会话身份：`ctx.sessionProjections`

**来源**：`@deepseek-ai/dsh-session-projection/README.md`

> ⚠️ **2026-11-05 订正（host-dev 查实）**：本节原先写的 `event.type === 'tm/identity-bound'`
> **照抄会让会话在重开时坏掉**，已废弃。见下方「不要自造事件类型」。

```text
const definition = {
  key: 'identity',
  stateSchema: identityStateSchema,
  stateVersion: 1,
  init: (_header, _inheritedEventCount) => ({ agentName: null }),
  apply: (state, event) => /* fold 既有事件，见下 */,
  wire: {
    viewSchema: identityViewSchema,
    view: state => ({ agentName: state.agentName }),
  },
}
```

### ❌ 不要自造 session event 类型

`practices.md:21` 硬规矩原文：
> **Do not append session events with a new `type`.** Readers accept an unknown stored event only when its
> envelope carries `ignorable: true`, and live `Session.append()` cannot set that marker,
> so **the Session would refuse to reopen**.

### ✅ 正确做法：fold 已经在日志里的既有事件

| 绑定来源 | fold 的事件 | 怎么取 |
|---|---|---|
| 模型侧 `dtm_bind` | `tool/call`，且 `name === 'dtm_bind'` | 从 `arguments` 里取 `智能体` / `项目` |
| 用户侧（UI） | `command/run`，且 `name === 'dtm-bind'` | 从 args 里取 |

两者都是**既有事件类型**，完全满足「session log 是唯一真相源 + fork/resume 可重建」，不触犯任何硬规矩。

**要点（其余不变）**
- `apply(state, event)` **必须同步**，且对不关心的事件**返回同一引用**（引用不变=零下游开销）
- `wire.view` 也必须复用引用才不触发发布
- host-only 单元（无 `wire`）不暴露给客户端
- **不要**从 `firstLiveSeq` 推断 fork 切点
- `register(definition)` 返回 disposer，可 yield 进 `ctx.effect()`

**对本插件的意义**：
- 会话身份绑定用它，**resume/fork 能正确恢复**（内存 map 会丢）
- 身份状态要显示在 UI → 加 `wire` 块
- **注入渲染必须同步取身份**：`ctx.systemPrompt.section` 的 `text(context)` 是同步的，
  所以宿主须提供 **`identityOfSync(agent)`**（异步版会让 prompt assembly 崩）

## 4. 客户端 ↔ 宿主：自定义 Remote namespace（**不是**自建 HTTP，也**不是**命令传 JSON）

**来源**：`dsh-api-gateway` / `dsh-typert-loader` / `settings-controller` / `pluginManager` 源码 + host-dev/client-dev 双向实测

> ⚠️ **2026-11-05 订正**：本节原先推荐 `ctx.commands.register()` 转调，**实践证伪**。
> 两条硬限制：① `commands/execute(agentId, line)` 必须绑 **agent**，而 `plugins.bundle.config` 是 **root scope**，
> 可能一个会话都没开；② `line` 是字符串，复杂对象只能自己序列化，脆且丑。

### ✅ 正确通道：`ctx.remote.<namespace>.<method>()`，session-free

**宿主侧**
```js
ctx.typert.register({
  package: 'dsh-tag-memory',
  face: 'host',
  schemas: [],
  invocations: [ /* 每个方法一条 descriptor */ ],
  model: { services: [], events: [], objects: [] },
})
// 服务实例上挂 typertRemote 绑定
```

**客户端侧**
```js
const unmount = await ctx.remote.$mount(contribution)   // 手写 contribution
ctx.inject(['remote.tagMemory'], ...)                   // 之后调 ctx.remote.tagMemory.xxx()
```

**关键事实（均已实测确认）**
1. **官方允许手写，不必用生成器**：`dsh-typert-loader:27` 原文
   *"Manual `ctx.typert.register()` remains available for contributions that do not use a `./typert` artifact
   (**hand-written wire schemas**, tests, non-loader compositions)."*
2. **天然 session-free**：`invocation: { kind: 'direct' }` 且不挂 lookup 时不解析任何 Context，
   直接从根 ctx 取服务（`dsh-api-gateway` apply 路径）。
3. **先例**：`settings/*`、`pluginInventory/list`、`pluginManager/*` 全部无 scope；
   root-scope 的插件管理页就这么调宿主。
4. **`$mount` 的真实校验**（实测）：
   - **入参** `codec.mode === 'strict'` 且必须带 `create`（所以入参必须写 Zod 工厂）
   - **`result` 完全不检查**（省一半 schema）
   - `assertExactArguments` 要求 `args` 是 plain object，**无参方法也要传 `{}`**
5. **`@deepseek-ai/dsh-typert-protocol` 不在浏览器基线模块表**，且官方禁止 import Client 包
   → 客户端需**内置 `toContribution()`**（只做 spec→descriptor 转换，不 require 外部包）

### 为什么不用 `@deepseek-ai/dsh-api-remotes` 注册我们的方法

它是**编译期硬编码 26 个贡献**的"应用级选择表"，第三方加不进去。要加只能 `ctx.remote.$mount()` 直挂。

### 命名约定

- namespace：**`tagMemory`**（端点如 `tagMemory/listEntries`）
- 工具命令前缀（若用）：**`dtm-ui-`**，与工具名 `dtm_` 明确区分
- **每个 endpoint 的参数名必须与宿主 descriptor 逐字一致**（曾发生 `payload` vs `request` 漂移，
  装上后编辑功能整个不可用，而双方自测都发现不了 → 已进跨模块契约测试）

## 5. UI 槽位：`plugins.bundle.config`（已定，不需再查）

**来源**：`dsh-cordis-client-runner/lib/client.js` 的 slot 目录 + `dsh-client-ui-plugin-manager` 源码（三处互证）

| 项 | 结论 |
|---|---|
| slot 名 | **`plugins.bundle.config`** |
| kind / scope | `keyed` / `root` |
| key | **本包包名 `dsh-tag-memory`** |
| owner props | 仅 `{ view: 'summary' \| 'page', form? }`；bundle 配置**只渲染 `page`** |
| 现有占用 key | 仅 `...cot-translation-bundle`、`...voice-input-bundle` —— 用自己包名不撞车 |

**为什么是这个**：《功能说明》§10.1 原文就写着「从「插件」列表进（`plugins.bundle.config`），**不占左侧栏**」——
规格与官方槽位正好对上。

**为什么不用 `settings.section`**：它会在**左侧栏设置导航里占一条**，与"不占左侧栏"直接冲突。

**slot 之外的全局标准 props**：所有 root slot 都带 `useSessions`（`GlobalStandardProps`），
但 `SessionListState` **只给列表，没有"当前选中会话"** —— 所以 UI 不依赖 session 上下文（见第 4 节的 Remote 通道）。

## 6. 插件包清单与安装

**来源**：`references/host-plugin.md` + `templates/decoration/package.json`

```json
{
  "name": "@local/my-decoration",
  "version": "1.0.0",
  "private": true,
  "type": "module",
  "exports": {
    ".": "./index.js",
    "./client": "./client.js",
    "./locale/*.json": "./locale/*.json",
    "./icon": "./icon.svg"
  },
  "files": ["index.js", "client.js", "cordis.patch.yml", "locale/*.json", "icon.svg"],
  "dsh": {
    "bundle": { "patch": "./cordis.patch.yml" },
    "client": {
      "platform": "web",
      "immediately": true,
      "inject": ["@deepseek-ai/dsh-client-ui-conversation"]
    }
  }
}
```

`cordis.patch.yml`：
```yaml
- insert:
    - id: my-decoration
      name: '@local/my-decoration'
```

**要点**
- `dsh.bundle.patch` 指向补丁；`dsh.client` 声明客户端
- `exports` 必须含 `./client`、`./locale/*.json`、`./icon`
- `files` 白名单**必须覆盖全部运行时文件**（新增模块要更新）
- 本地目录安装是**链接**，`files` 不过滤链接目录 → **更要保证 `内部文档/` 不在发布路径**
- `locale/en.json` 里 `{ "meta": { "title": "...", "description": "..." } }`
- icon ≤ 256KiB，SVG/PNG/JPEG/WebP，必须在包内
- **安装只用 `install_bundle`**；返回的 `application` 和 `warnings` 决定是否真生效

## 7. 给各开发者的结论摘要

| 角色 | 必须照这个写 |
|---|---|
| **preset-dev** | `ctx.tools.register(defineTool({...}))`；`ctx.systemPrompt.section({name,order,text})`，含 `{{` 时设 `interpolate:false` |
