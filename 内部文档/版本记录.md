## v0.1.3 — 存储格式定为 CSV（2026-11-05）

**记忆库本体：`store/memory.csv`（9 列）**。台账 `records/*.jsonl` 仍用 JSONL（纯机器读，无需人改）。

### 决策依据（实测，非推测）

| 方案 | 每条字节 | 固定开销 | 5000条 |
|---|---|---|---|
| **CSV** | **159** | **90** | **0.76 MB** |
| MD 表格行 | 183 | 114 | 0.87 MB |
| MD 卡片 | 235 | 166 | 1.12 MB |
| JSONL | 282 | 213 | 1.34 MB |

- **空间：CSV 最省**，唯一比 Markdown 还省的格式。JSONL 因每行重复字段名最费。
- **"自由标签用 CSV 很麻烦"是被夸大的**：写 `join('|')` 1 行、读 `split('|')` 1 行；
  **比对完全不受影响**——实测条目 3 标签 / query 2 标签 / 命中 2 → `e_ratio=0.667`、`q_ratio=1`，
  命中否决与打分都在内存数组上做。
- **真正的坑只有一个**：标签含 `|` 会串位（实测 3 个标签读回 4 个）。
- **真实成本**：一次性实现 RFC4180 解析器（引号、`""` 转义、字段内换行）。
  实测证明简单 `split(',')` 必然错——正文一个 ASCII 逗号就让 9 列变 10 列；加引号后简单 split 仍错。
  **CSV 有成熟标准可循；Markdown 表格同样怕 `|` 和换行，却无标准解法。**

### 为什么不选另外两个

- **不选 Markdown 表格**：Markdown 表格单元格**语法上不能含换行**，而 `主要内容` 不设上限、整合后的流程必然很长带换行。绕开就得把换行改写成 `<br>`，反而加重手动修改负担。
- **不选 SQLite**：出问题时用户只能靠模型救，无法手动干预。**记忆库必须保持"人能看懂、能改"。**

### 新增规则

1. **保留字符 `|` 一律拒写**：标签内容含 `|` → 报错并**点名是哪个标签**、说明原因，让模型改写后重调。
   **不做程序偷偷替换**（会静默改变原意）。成本低：模型收到明确原因改一个词即可。
2. **CSV 序列化硬规则**（《架构说明》§8.1）：RFC4180 转义、`自由标签` 用 `|` 分隔、表头必须存在、程序按列名定位。
3. **UI 条目编辑**（《功能说明》§10.3 新增）：
   - 可改：`形态`/`项目`/`智能体`/`自由标签`/`稳定性`/`状态`
   - **不可改**：`主要内容`（一手材料）、`编号`（唯一标识）、`时距`（程序计数）
   - 走宿主方法，**与 `dtm_retag` 共用同一实现**（一个操作、两个调用者）
   - 保存后写 `records/tidy.jsonl`，`action=user_edit`
   - 改 `项目`/`智能体` 给候选列表，减少打错字导致隔离失效

> **用户确认的工作方式**：通过插件 UI 的表格界面修改，**不是用 Excel**，
> 所以"改错一个逗号毁全库"的风险不存在。

## v0.1.2 — 对齐 DSH 官方插件规范（2026-11-05）

依据 **本机一手官方文档**（`@deepseek-ai/dsh-agent-preset/skills/cordis-plugin-development/`）核对了全部 7 份说明，
修掉 4 处与官方要求冲突的地方 + 统一术语。**记忆系统内部运行逻辑一字未改**（六形态/标签/打分/隔离/稳定性/JSONL 记录全部原样）。

**核心判断**：冲突全部落在"插件与 Harness 的对接层"，属于"换管道、不换引擎"。

### 冲突修正

| # | 官方规则 | 原设计 | 改为 |
|---|---|---|---|
| A | 只用 `install_bundle`，不许手写 profile 的 `package.json`/`cordis.patch.yml`、不许在 profile 目录跑 pnpm | 旧 `install.mjs` 直接写 profile 清单与补丁 | 统一走 `plugin_manager` 的 `install_bundle` |
| B | 客户端走 Client-callable Host 入口（`ctx.remote.commands.execute()` 等）+ storage service；一个操作两个调用者 | 自建 `/tag-memory-api` + `connection.requestRejection` + fail-closed 503 | **自建方案作废**；改为宿主方法 + Client-callable 入口；UI 与工具共调同一方法 |
| C | 禁止 import 任何 Harness Client 包（如 `dsh-client-ui-primitives`） | 技术选型写"先看 ui-primitives" | 改为"自己写控件 / 复制宿主实现" |
| D | 验证不许造假：不另起浏览器、不找光栅化工具、**不模拟 React/DOM**、mock 截图不算验证 | 验收要求"假 React 渲染冒烟" | **已废止**；改为引擎单测 + 工具注册冒烟 + manifest/语法校验 + 视觉如实报告 |
| H | 可调值放插件 `Config`，用户在 `cordis.patch.yml` 改 | 阈值只在包内 `scoring.json` | 默认值仍在 templates，可调项另在 `Config` 暴露 |

### 术语统一

- **"三半结构 / 宿主半 / 智能体半 / 客户端半" → "插件结构与三个入口 / 宿主入口 / 预设入口 / 客户端入口"**（全库 17 处清零）。
  理由：① "半"非官方术语；② "三半"像三个并列系统，实为一个插件的三个入口；③ "智能体半"易误以为独立进程。
  官方对应：Host plugin / Agent preset / Client module。
- 新增总括句：**"一个插件，一份引擎，三个入口"**——三者共享 `lib/engine/*` 同一份纯逻辑。
- "智能体半"的实现载体由"`preset.js` 单文件"更正为"预设 YAML 声明 + 插件注册（`ctx.tools.register`）"。

### 其他对齐

- 会话身份存取：从"内存 `sessionId → 身份名` 映射"改为 **`ctx.sessionProjections`**（官方："session log 是唯一真相源"，纯内存映射在 resume 后会丢）。**"未绑定就不读写"铁律不变**。
- 工具注册写法补全为 `ctx.tools.register(defineTool({...}))`。
- 补 `agent.ctx` 双 owner 注意事项、`wire.view`、slot 内 React（禁 iframe）。
- 架构说明 §十四 参考材料改为指向**本机官方文档路径**（含 6 份 references 与 2 套模板）。
- `待查证问题.md`：问题 1/2/3 标记**已解决**并写明结论；补"另外三条官方硬规矩"。
- `开发计划.md` 阶段 0 改写为"动手核实实现细节"（不再查已解答的问题）；阶段 1 加"一个操作两个调用者"。
- `功能说明.md` 验收项按官方重写（客户端/安全与接口/安装与发布三组）。

## v0.1.1 — 技能复审后的一致性修订（2026-11-05）

用 `mattpocock/skills` 的 `codebase-design` / `domain-modeling` / `grilling` 三把透镜做了第二轮互检，按主子的裁定修掉 8 处硬矛盾 + 若干悬空项：

**主子裁定（本轮拍板）**
1. **"四状态" → 澄清为"程序填的 4 个字段"**（`编号`/`稳定性`/`时距`/`状态`）。这四个字段各有自己的值域（`稳定性` 三态、`状态` 三态、`时距` 计数、`编号` 唯一ID），**不是"四个状态值"**。已在架构说明、功能说明验收、标签字典、流程_写入四处统一。
2. **取代/归档 = 整理的工作**。写入只追加新行，永不改写已有条目。已在功能说明 §6.5、流程_写入、流程_整理 三处对齐。
3. **feedback 落盘 = 占位参数**（后期专项设计定稿）。当前只确定：它是稳定性状态机唯一数据源，`verdict ∈ {ok, wrong, unused}`；三种候选落盘形态（原地更新原行 / 另起 `action=feedback` 行 / 只记 tidy.jsonl）待定。
4. **同轮频繁错召 → 触发整理**（不属读写）。口径："错误"= 被召回但与需求不符，不是查空。整理是条件触发的临时任务；read/write 只记录不改。已写入流程_整理 §5.4 新增小节 + 功能说明触发表。
5. **工具名统一 `dtm_` 下划线版**。清除 `dtmbind`/`dtmmrecall`/`dtmm_*` 等双 m 拼写。
6. **UI 手动改条目路由 = 前端设计阶段再定**，架构接口表不预设端点（删除凭空出现的 `heal`）。
7. **`heal` 端点删除**（AI 自行添加、无定义）。

**顺带修掉**
- `records/tick.jsonl` 悬空引用删除（架构数据目录改为 write/read/tidy）。
- 路径写法统一为 `<dataDir>/records/`。

- 归纳阈值 3 vs 升格阈值 4 补充解释（风险不对称）。

- 跨形态命中（形态不中+标签满+时距满=50≥40）定性为**有意设计**并写明理由与调参方式。
- 开发计划 `dtm_feedback` 兜底措辞改为"触发整理"。

**新增硬性规定（主子本轮下达）**
