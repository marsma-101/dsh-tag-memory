## 一、版本号规则（重要，先看这里）

**本项目存在两套版本号，不要混用：**

| 场景 | 版本号 | 说明 |
|---|---|---|
| **对外发布版** | **`v1.0.0`** | 插件正式写出来、对外公布时用这个 |
| **开发期内部版** | `v0.1.x` | 仅用于本文件记录内部定稿节点，**不对外** |

### 为什么对外是 v1.0.0

之前的 v0.1 / v0.2 / v0.3 都是**技术架构上的小迭代**，标签设计还是**老方案**。
从本版开始引入 **「固定标签 + 自由标签」双标签体系**（固定标签=形态/项目/智能体，自由标签=召回主信号），
召回准确率有实质性提升——**这是整体架构的更新，不是补丁**，所以正式发布定为 **v1.0.0**。

### 开发期怎么记

**在插件正式写出来之前，不新增对外版本号。** 内部继续用 `v0.1.x` 记录定稿节点即可；
写完、对外公布时统一标为 `v1.0.0`。

> 当前内部版本：**`v0.1.5`**（开发准备：团队与流程之后的最新节点）

### 3 个真实缺陷（本地测试全绿也发现不了）

| # | 缺陷 | 后果 | 修法 |
|---|---|---|---|
| ① | `preset/index.js` 导出 `export const Config = {}` | **整个插件行 activation 失败**（`cordis` 的 `resolveConfig` 要求 `~standard`，空对象不是"没有 schema"） | 不导出 Config，可调值走 engine `templates/*.json` |
| ② | `bindIdentity` 只返回不存储 | `identityOf` 恒 null → **所有写入被拒**（bind ok 但 write 报 UNBOUND_IDENTITY） | 加 `WeakMap` 进程内兜底，`identityOfSync` 改为「投影优先，兜底其次」 |
| ③ | `writeEntry`/`recall` 不自动填绑定值 | 省略传值时 engine 判 `PROJECT_EMPTY`；`recall` 漏兜底 `项目` 使 `filtered` 归零、**查不到刚写的记忆** | 两处都「绑定值兜底，显式值优先」 |

**根因统一**：假 `ctx` 绕过了框架的 `resolveConfig`、模块解析、Remote 挂载——
**这些被"绕过"的东西，恰恰是真实环境最先崩的地方。**

### 关键实现决策（均有源码依据 + 独立实测）

| 决策 | 依据 |
|---|---|
| UI↔宿主走**自定义 Remote namespace `tagMemory`**（session-free） | `settings/*`/`pluginManager/*` 同构先例；`dsh-typert-loader:27` 允许手写；实测 `$mount` 通过 |
| 身份投影 **fold 既有 `tool/call` + `command/run`**，不造新 event type | `practices.md:21`：新 type 会让会话拒绝重开（**照抄旧探明结论会静默坏用户会话**） |
| UI 槽位 = **`plugins.bundle.config`**，key = 包名 | 与《功能说明》§10.1 原文一致；三处互证 |
| 预设走**普通宿主行**，不用 agent-preset 行 | 第一方工具全这么装；`ctx.tools.register` 进全局层，装上即对所有 agent 可用 |
| 客户端**内置 `toContribution()`** | `dsh-typert-protocol` 不在浏览器基线模块表 + 禁止 import Client 包 |

### 三处规格裁定（已落文档）

1. **`架构说明` §13.2｜CSS token**：可豁免 `--ds-font-family-code`。
   依据：107 个 alias 中 font 类为 0、官方参考页自己在用、内联会拍平用户字体自定义链。
   **这是对官方 `keep only --dsw-alias-*` 的有据放宽，不是放水。**
2. **`架构说明` §13.3｜800 行线**：判定为"该拆了的信号"而非硬线。
   首版不拆（拆完没人验过 / 引入 chunk 加载失败模式 / 收益是可维护性）。
   **拆分时机 = 首次真实安装验证后（v1.1）或单文件超 3000 行。**
3. **`流程_写入` §5.2｜自由标签非空**：空数组拒写（`e_ratio` 恒 0 → 必被否决 → 废条）。

### 本轮抓到的真实缺陷（双方自测都发现不了的）

1. **跨模块参数名漂移**：宿主 `request` vs 客户端 `payload` → 装上后编辑功能整个不可用。
   已修 + **已进跨模块契约测试**（逐方法双向比对 + 打印计数）。
2. **`inject` 求值时机**：`() => hasApi(ctx) ? ... : null` 同步求值 + 异步 `$mount` → 页面永久"未接线"。改为惰性代理。
3. **全新安装必崩**：锁文件在未创建的 `store/` 下 → ENOENT。已加 `ensureDirs()`。
4. **身份投影自造事件类型**：会静默坏会话。已改为 fold 既有事件。

### 方法论教训（已写进 `团队_开发流程.md`）

1. **判据必须先自证有效**——`_getActiveHandles` 那条恒绿假阳性（连 ref 的都不返回），
   比没有判据更危险。做法：先做对照组证明尺子准，再量东西。
2. **跨模块最容易漂移的是字段名，不是逻辑**——双方自测都通过也可能装不上。
3. **脚本化改源码后必须立刻 `--check`**，且禁止交付前批量正则替换。
4. **检查脚本必须打印计数**，"没报错"不等于 PASS。

### 未验证（如实）

- **视觉全部未验**：`3080` → HTTP 401，无浏览器控制。页面外观 / 明暗主题 / `slot entry crashed` /

### 2. 补全「双标签体系」定义（此前文档缺失）

**这是 v1.0.0 的核心概念，之前只有零散提及，没有正式定义。** 已在《功能说明》新增 §三：

| 类别 | 包含 | 特点 | 召回作用 |
|---|---|---|---|
| **固定标签** | `形态`、`项目`、`智能体` | 取值有限、字典约束 | 硬筛 + 强加权（项目/智能体隔离；形态 50 分） |

**代价转移**：召回质量从"程序切词算法"转到**模型打标签的纪律**，所以《标签字典》必须每轮注入。

## v0.1.3 — 存储格式定为 CSV（2026-11-05）

**记忆库本体：`store/memory.csv`（9 列）**。台账 `records/*.jsonl` 仍用 JSONL（纯机器读，无需人改）。

### 决策依据（实测，非推测）

| 方案 | 每条字节 | 固定开销 | 5000条 |
|---|---|---|---|
| **CSV** | **159** | **90** | **0.76 MB** |
| MD 表格行 | 183 | 114 | 0.87 MB |
| MD 卡片 | 235 | 166 | 1.12 MB |
| JSONL | 282 | 213 | 1.34 MB |

- **空间：CSV 最省**，唯一比 Markdown 还省的格式。JSONL 因每行重复字段名最费。
- **"自由标签用 CSV 很麻烦"是被夸大的**：写 `join('|')` 1 行、读 `split('|')` 1 行；
  **比对完全不受影响**——实测条目 3 标签 / query 2 标签 / 命中 2 → `e_ratio=0.667`、`q_ratio=1`，
  命中否决与打分都在内存数组上做。
- **真正的坑只有一个**：标签含 `|` 会串位（实测 3 个标签读回 4 个）。
- **真实成本**：一次性实现 RFC4180 解析器（引号、`""` 转义、字段内换行）。
  实测证明简单 `split(',')` 必然错——正文一个 ASCII 逗号就让 9 列变 10 列；加引号后简单 split 仍错。
  **CSV 有成熟标准可循；Markdown 表格同样怕 `|` 和换行，却无标准解法。**

### 为什么不选另外两个

- **不选 Markdown 表格**：Markdown 表格单元格**语法上不能含换行**，而 `主要内容` 不设上限、整合后的流程必然很长带换行。绕开就得把换行改写成 `<br>`，反而加重手动修改负担。
- **不选 SQLite**：出问题时用户只能靠模型救，无法手动干预。**记忆库必须保持"人能看懂、能改"。**

### 新增规则

1. **保留字符 `|` 一律拒写**：标签内容含 `|` → 报错并**点名是哪个标签**、说明原因，让模型改写后重调。
   **不做程序偷偷替换**（会静默改变原意）。成本低：模型收到明确原因改一个词即可。
2. **CSV 序列化硬规则**（《架构说明》§8.1）：RFC4180 转义、`自由标签` 用 `|` 分隔、表头必须存在、程序按列名定位。
3. **UI 条目编辑**（《功能说明》§10.3 新增）：
   - 可改：`形态`/`项目`/`智能体`/`自由标签`/`稳定性`/`状态`
   - **不可改**：`主要内容`（一手材料）、`编号`（唯一标识）、`时距`（程序计数）
   - 走宿主方法，**与 `dtm_retag` 共用同一实现**（一个操作、两个调用者）
   - 保存后写 `records/tidy.jsonl`，`action=user_edit`
   - 改 `项目`/`智能体` 给候选列表，减少打错字导致隔离失效

> **用户确认的工作方式**：通过插件 UI 的表格界面修改，**不是用 Excel**，
> 所以"改错一个逗号毁全库"的风险不存在。

## v0.1.2 — 对齐 DSH 官方插件规范（2026-11-05）

依据 **本机一手官方文档**（`@deepseek-ai/dsh-agent-preset/skills/cordis-plugin-development/`）核对了全部 7 份说明，
修掉 4 处与官方要求冲突的地方 + 统一术语。**记忆系统内部运行逻辑一字未改**（六形态/标签/打分/隔离/稳定性/JSONL 记录全部原样）。

**核心判断**：冲突全部落在"插件与 Harness 的对接层"，属于"换管道、不换引擎"。

### 冲突修正

| # | 官方规则 | 原设计 | 改为 |
|---|---|---|---|
| A | 只用 `install_bundle`，不许手写 profile 的 `package.json`/`cordis.patch.yml`、不许在 profile 目录跑 pnpm | 旧 `install.mjs` 直接写 profile 清单与补丁 | 统一走 `plugin_manager` 的 `install_bundle` |
| B | 客户端走 Client-callable Host 入口（`ctx.remote.commands.execute()` 等）+ storage service；一个操作两个调用者 | 自建 `/tag-memory-api` + `connection.requestRejection` + fail-closed 503 | **自建方案作废**；改为宿主方法 + Client-callable 入口；UI 与工具共调同一方法 |
| C | 禁止 import 任何 Harness Client 包（如 `dsh-client-ui-primitives`） | 技术选型写"先看 ui-primitives" | 改为"自己写控件 / 复制宿主实现" |
| D | 验证不许造假：不另起浏览器、不找光栅化工具、**不模拟 React/DOM**、mock 截图不算验证 | 验收要求"假 React 渲染冒烟" | **已废止**；改为引擎单测 + 工具注册冒烟 + manifest/语法校验 + 视觉如实报告 |

### 术语统一
