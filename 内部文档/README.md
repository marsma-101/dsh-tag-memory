# 内部文档（不发布、不上传）

> **这个文件夹里的东西不进插件包、不上传到任何地方，但必须纳入 git 版本控制。**

## 放什么

| 文件 | 作用 |
|---|---|
| `功能说明.md` | 这个插件要做什么（需求与功能说明书） |
| `架构说明.md` | 架构事实与设计约束（开发前必读） |
| `流程_写入.md` | 写入链路的执行细节 |
| `流程_读取.md` | 读取链路的执行细节 |
| `流程_整理.md` | 整理链路的执行细节 |
| `待查证问题.md` | 开发前需单独查证的技术问题 |
| `开发计划.md` | 分阶段开发计划 |
| `版本记录.md` | 定稿节点与决策留档 |

## 不放什么

- **`标签字典.md` 不在本文件夹**。它是**每轮注入给模型**的运行时资产，将来随插件打包（落 `lib/engine/templates/`），所以留在仓库根目录。

## 为什么单独放

这些文件是**给人和开发者看的说明书**，不是插件运行时需要的东西。
混在插件根目录会带来两个风险：
1. 被 `package.json` 的 `files` 通配进去，跟着插件一起发布/上传；
2. 被误传上去后成为对外可见的项目内部设计。

## 怎么保证它不被带出去

三重保险：
1. `.npmignore` 明确排除 `内部文档/`；
2. `package.json` 的 `files` 白名单**只列必要文件**，不用通配；
3. 归档同步脚本 `ops/privhub-init.ps1` 只推根目录的 `标签字典.md` 与插件运行所需文件，不推本文件夹。

> 改本文件夹内容后，记得在 `版本记录.md` 里记一笔，并提交 git。
