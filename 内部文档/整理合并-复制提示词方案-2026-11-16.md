# 整理/合并：复制提示词到新会话（最终方案）

**日期**：2026-11-16
**决策**：用户定案——插件**生成一段整理/合并提示词**，用户复制，开新会话粘贴给模型执行。
**相比上一版砍掉了什么**：不需要会话角色识别、不需要工具按会话过滤、不需要 UI 新按钮、不需要插件调模型。

---

## 一、为什么这个方案最简且最稳

### 1.1 关键洞察

**新会话里同样加载着本插件。** 所以：

- 10 个 `dtm_*` 工具**天然可用** → 提示词不用列工具清单
- 写入规则**已经每轮注入** → 提示词不用重复「形态怎么判、标签怎么打」
- 身份/项目由 `dtm_bind` + 程序自动填 → 提示词不用交代归属

**提示词只需要补充「日常注入里没有的东西」**：本次任务是什么、要处理哪些条目、输出什么格式、有哪些本任务专属的约束。

这让提示词从「一份完整手册」缩成「一张任务单」。

### 1.2 三种方案对比

| | 上一版（会话角色） | **本方案（复制提示词）** | 更重的方案（插件调模型） |
|---|---|---|---|
| 需要改 UI | 是 | **否** | 是 |
| 需要识别会话角色 | 是 | **否** | — |
| 需要工具过滤 | 是 | **否** | — |
| 需要宿主反向通道 | 否 | **否** | **是（未验证）** |
| 用户操作 | 点按钮 | **复制粘贴** | 无 |
| 实现量 | 中 | **小** | 大 |

**代价**：用户要多做一步「复制粘贴」。但换来的是**零架构改动 + 零未知依赖**，值得。

### 1.3 技术上怎么落地

新增两个工具（或一个工具的两种模式），**只输出文本，不改库**：

```
dtm_tidy_prompt   → 返回一段可复制的整理提示词（含候选清单）
dtm_merge_prompt  → 返回一段可复制的合并提示词（含来源解析结果）
```

用户流程：

```
① 在会话里说「整理记忆库」/「导入记忆文件」
② 模型调 dtm_tidy_prompt / dtm_merge_prompt
③ 插件返回一段提示词文本（模型原样展示给用户）
④ 用户复制 → 开新会话 → 粘贴
⑤ 新会话里的模型按提示词执行，用现有工具完成整理/合并
```

**插件全程不碰库**（`*_prompt` 是只读的），真正改库由新会话里的模型用
`dtm_retag` / `dtm_archive` / `dtm_supersede` / `dtm_write` / `dtm_merge` 完成。
每一步都有工具自带的校验与备份。

## 二、整理提示词（核心产物）

### 2.1 插件生成的完整文本

````markdown
# 记忆库整理任务

你在整理 dsh-tag-memory 的记忆库。本会话已加载该插件，`dtm_*` 工具可直接用。

## 一、本次任务

程序已按规则挑出 **12 条**需要整理的条目，清单在最后。
你的任务是**逐条判断该怎么处理**，然后用工具执行。

请先调 `dtm_review` 看清这些条目的完整内容（清单里只有编号和摘要）。

## 二、可选动作

| 动作 | 什么时候用 | 用哪个工具 |
|---|---|---|
| **补标签** | 内容有价值，但标签空/不合格 | `dtm_retag`（传 形态 + 自由标签） |
| **归档** | 内容已失效、过时，或本身不该存在 | `dtm_archive` |
| **取代** | 这条已被另一条更好的取代 | `dtm_supersede` |
| **跳过** | 看过没问题 | 不调工具，在报告里说明 |

⚠️ `dtm_retag` **必须带 `basis`**（依据），缺了会被拒。
依据写法：说明你为什么这么改，例如
`"整理：原标签为空，按内容补为 技能 + [npm,发布,2FA]"`。

⚠️ `dtm_retag` **不能改** `编号` / `主要内容` / `项目` / `智能体` / `时距`。
- 内容写错了要改 → 用 `dtm_supersede` 写一条新的取代它
- 归属不对 → 那是环境事实，你不能改，报给用户

## 三、判断要点

### 3.1 空标签的条目

读内容 → 按写入规则补 `形态` 和 `自由标签`。
**补不出合格标签的，说明这条本身可能没价值 → 归档。**

### 3.2 标签是噪声的条目

纯数字（如 `3190`）、单字（如 `坑`）、来源标记（如 `原话`、`推断`）**不是有效标签**，
它们几乎不可能被检索到。换成有检索价值的实词。

### 3.3 疑似重复

程序只能按「主要内容相似度」挑出来，**它不判语义**。
你要**真的读完两条**再判：

- 内容确实讲同一件事 → `dtm_supersede`（保留信息更全的那条，把另一条取代）
- 只是主题相近（比如都讲 npm 发布，但一个讲 2FA、一个讲代理）→ **不算重复，保持独立**

### 3.4 形态为空的条目

按「将来怎么找它」判形态，不要按「它长什么样」判。

## 四、自由标签的要求（本次任务重点）

用户明确要求：**自由标签要尽量详细，并尽量跟其他条目区分开**。

具体做法：

1. **从三个方向拆**：内容关键词 / 作用 / 注意事项
2. **避开泛词**。库里这些词已被用滥（附频次），靠它们找不到东西：
   ```
   dsh(26)  推断(16)  原话(14)  通用(11)  ...
   ```
3. **给它独有词**。想「这条将来会因为什么被想起」，就把那个词打上。
   - 差：`["npm","发布"]` —— 一堆条目都有
   - 好：`["npm","发布","2FA","Bypass token","Trusted Publishing"]`

4. 数量 1~20 个，**不含 `|`**。

## 五、输出要求

每处理完一批，给一份**人读的报告**：

```
处理结果：
- M-20261011-003  补标签  技能 + [npm,发布,2FA,Trusted Publishing]
- M-20261012-007  归档    内容已被 M-20261116-011 覆盖
- M-20261012-009  跳过    标签正常，无需改动
```

最后汇总：改了几条、归档几条、跳过几条。

|---|---|---|---|---|
| M-20261011-003 | （空） | （空） | 空标签 | npm 发布免 OTP 的正解… |
| M-20261012-007 | 技能 | 原话,推断 | 噪声标签 | 代理 TLS 证书问题… |
| ... | | | | |
````

### 2.2 提示词里的动态部分

插件生成时填入：

| 占位 | 来源 |
|---|---|
| 候选清单 | `diagnose.mjs` 挑出（空标签 / 噪声标签 / 疑似重复 / 形态空） |
| 频次表 | `vocab.mjs` 已有的频次统计，取 top 10 |
| 条数统计 | 同上 |

**固定部分**（动作说明、判断要点、标签要求、输出格式）是常量，写死在模板里。

## 三、合并提示词（核心产物）

### 3.1 插件生成的完整文本

````markdown
# 记忆库合并任务

你在把一份**外来记忆文件**并入 dsh-tag-memory 的记忆库。
本会话已加载该插件，`dtm_*` 工具可直接用。

## 一、来源信息

- 文件：`C:\Users\...\other-agent-memory.md`
- 识别格式：**Markdown**（按 `#`/`##` 标题切块）
- 解析出：**47 条**候选
- ⚠️ 若格式是「纯文本兜底」，会有这句：本文件未能识别为已知格式，
  已按空行切块，**切分可能不准**，请自行核对。

## 二、你必须做的三件事

不管来源是什么格式，每条都要按**写入规则重新表达**：

### 1. 读懂内容

先理解这条记忆在讲什么。**一条只记一件事**；如果原文混了几件事，**拆成多条分别写**。

### 2. 判形态（6 选 1）

单件事怎么做→`技能`；多件事次序→`流程`；必须/禁止→`规则`；
喜欢/倾向→`偏好`；客观陈述→`事实`；可复用格式/清单→`模板`。
判据是「**将来怎么找它**」，不是「它长什么样」。

### 3. 打自由标签

1~20 个离散实词，不含 `|`。从三方向拆：内容关键词 / 作用 / 注意事项。

**本次重点：尽量详细，并尽量与其他条目区分开。**
库里这些泛词已被用滥（附频次），别指望靠它们被找到：
```
dsh(26)  推断(16)  原话(14)  ...
```

## 四、你不能改的字段（重要）

| 字段 | 规则 |
|---|---|
| `项目` | **原样复制来源里的值**，不重新推断、不映射。来源为空 → `引入` |
| `智能体` | **同上** |
| `稳定性` | 一律 `观察`（首次落库规矩，不自称稳定） |
| `时距` | 一律 `1`（写入初值） |
| `状态` | 一律 `生效` |

`项目`/`智能体` 为什么必须原样复制：**归属是环境事实，不是模型的判断**。
一条记忆属于哪个项目/哪个身份，只有来源方知道。猜错会污染召回。

## 五、执行方式

### 方式 A：用 `dtm_write` 逐条写（推荐，简单）

对每条候选，调一次 `dtm_write`：
- `主要内容`：按上面的规则重新表达
- `形态`：你判的
- `自由标签`：你打的

`项目`/`智能体` 由程序按当前会话填。
⚠️ **如果来源的项目/身份与当前会话不同**，这样写会把归属写成当前的，
与「原样复制」要求冲突 → 这种情况用方式 B。

### 方式 B：先导出成 CSV 再 `dtm_merge`（保留原归属）

1. 把每条整理成一行，按九列格式写成 CSV
2. `dtm_merge` 该 CSV

适合「来源归属明确且需要保留」的场景。

**判断标准**：来源的项目/身份 == 当前会话的 → 用 A；不同 → 用 B。

## 六、输出要求

每写完一批给一份报告：

```
已合并 12/47：
- 第 1 条 → 技能 + [npm,发布,2FA]
- 第 2 条 → 规则 + [兜底,测试有效性]
- 第 3 条：原文混了两件事，拆成两条
...
```

最后汇总：成功几条、跳过几条（及原因）、拆分成几条。
````

### 3.2 格式解析（插件侧）

| 格式 | 判定 | 解析 |
|---|---|---|
| 本插件 CSV | 首行含九列表头 | `readLibraryCsv` |
| Markdown | 扩展名 `.md` | 按 `#`/`##` 标题切块，代码块内不切 |
| JSON | 首字符 `{`/`[` | 找数组，取 `content`/`text`/`memory`/`主要内容` 等键 |
| 纯文本 | 兜底 | 按空行切块，**提示词里明说「可能不准」** |

**不做 SQLite 直读**（零依赖硬约束），提示词里注明「请先导出成 CSV/JSON」。

### 实施中发现并修掉的三个真实缺陷

| 缺陷 | 根因 | 修法 |
|---|---|---|
| `parseCsv(单行)` 把首行当 header，`rows[0]` 是 undefined → 表头判定永远失败 | 误用 core 接口 | 表头判定用 `.header`，CSV 解析改用 `rowsToRecords` |
| `原话` 等来源标记未被判为噪声 | 传了空 `Set` 给 `isUsefulTag` | 改用 `resolveExclusions()` 合并内置名单 |
| 链式贪心把 A≈B≈C 的重复组拆成 2 条 | 只拿第一条逐个比 | 改用并查集 |

另修一处设计问题：`mergePrompt` 原本先过 `confinePath` 再 stat，导致
「文件不存在」被误报成「路径越界」。改成**先确认存在、再过围栏**，
不改现有 `confinePath`（它还服务 mergeLibrary 等既有调用方）。

## 七、这个方案的已知代价

| 代价 | 说明 | 是否可接受 |
|---|---|---|
| 用户要复制粘贴 | 多一步操作 | ✅ 换来零架构改动 |

| 整理结果无法自动校验 | 新会话里模型自己调工具，插件只做单次校验 | ✅ 工具自带校验（`dtm_retag` 必须带 basis 等） |
