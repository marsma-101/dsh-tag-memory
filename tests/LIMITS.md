# 测试能力边界（假 ctx 覆盖不到什么）

> **这份文件是 `tests/**` 测试结果的可信边界声明。**
> 读任何一份 qa 报告前，请先读这份。
>
> 起因：本地 **177 条全绿**，装进真实容器（`dsh-text-codeing`，DSH 0.2.1-rc.2 / Node v22.23.3 / Linux）
> 后暴露 **3 个真实缺陷**。三个**全部**落在本文列出的盲区里。
> 这不是测试写得不认真，是**假 ctx 这种测法从原理上就够不到**。

---

## 一、结论先说

| 层 | 覆盖情况 | 可信度 |
|---|---|---|
| **纯逻辑**（`lib/engine/**`） | 充分（101 条） | ✅ 高——引擎不依赖框架，假 ctx 与真环境等价 |
| **业务行为**（落盘/未绑定/整理纪律/契约） | 充分（54 条） | ✅ 高——但仅限"直接调服务方法"这条路径 |
| **框架契约**（Config schema / 模块解析 / 生命周期） | **未覆盖** | ❌ **盲区** |
| **事件链路**（`tool/call` → 投影） | **未覆盖** | ❌ **盲区** |
| **真实调用形态**（preset → 宿主 的参数传递） | **部分** | ⚠️ 假 ctx 直接调方法，绕过了 wire 层 |
| **视觉/渲染** | **未覆盖** | ❌ **盲区**（无浏览器控制） |

## 二、真容器暴露的 3 个缺陷（全部在盲区内）

### ① `preset/index.js` 导出空 `Config = {}` → 整个插件行激活失败

```js
// cordis/lib/index.js:958 resolveConfig
if (!runtime.Config) return config;                              // 空对象 ≠ undefined，过了
const result = runtime.Config['~standard'].validate(config);      // undefined.validate → TypeError
```

**为什么假 ctx 测不出**：我的 `_fake-ctx.mjs` 里 `apply(ctx, config)` 是**直接调用**，
根本没有 `resolveConfig` 这一步。框架在调用 `apply` **之前**做的契约校验，**完全不在测试路径上**。

### ② `bindIdentity` 只返回不存储 → `identityOf` 恒为 null → 所有写入被拒

**为什么假 ctx 测不出**：我的 `_host-ctx.mjs` 用
```js
services.sessionProjections = { stateOf: () => identityRef.value, ... }
```
**直接伪造了投影返回值**。真实环境里投影靠 `tool/call` / `command/run` **事件积累**，
而宿主方法被**直接调用**时事件根本没进投影 → 投影恒为空。
**我的 mock 恰好把这个缺陷掩盖了**——这在方法论上叫"用假实现验证假实现"。

### ③ `writeEntry`/`recall` 曾用绑定值兜底省略字段（已彻底移除）

- **当时的实现**：`writeEntry` 省略 `项目` 时用 `identity.项目` 补；`recall` 只兜底 `智能体` 不兜底 `项目`
  → 空串参与硬筛 → **`filtered` 归零**，表现为"记忆插件没生效"
- **为什么这是错的**：兜底不是"帮模型省事"，是"程序替模型做决定"。项目归属猜错，
  这条就串到别的项目，事后整理也分不出来。用户裁决：**被拒就对了**。
- **现在的行为**：缺 `项目`/`智能体` 一律拒，返回 `blocked` + `errors` 点名缺哪个字段、
  合法值域、去哪查标准（`标签字典.md`「字段标准」）。模型据此补全重试。

**为什么假 ctx 测不出**：我的测试**总是显式传全字段**（`INPUT` 常量里齐全）。
模型实际行为是**省略**——而"省略"这条路径我从没走过。

> **教训**：测试用例的"输入形态"如果只覆盖一种写法，另一种写法就是盲区。
> 例如"模型一定要传全"是我的假设，不是规格。
>
> **更深的教训**：发现"省略就失败"之后，第一反应是**加兜底让它能过**——这是错的。
> 正确做法是让失败**显式暴露**（拒绝 + 说明 + 指向标准），由模型补全。
> 加兜底只是把缺陷藏起来，进不了生产环境。

## 三、完整盲区清单

### A. 框架级契约（假 ctx 结构性绕过的）

| 项 | 说明 |
|---|---|
| `Config` / `~standard` schema 校验 | `resolveConfig` 在 `apply` 之前，假 ctx 没有 |
| 插件清单解析（`exports` / `dsh` 字段） | `install_bundle` 才走，我只做了静态 JSON 校验 |
| 模块解析（`@deepseek-ai/dsh-tools` 等运行时包） | **已消除**：preset 改为自带 `define-tool.js`（零外部依赖），不再 import 任何框架包。原 shim（`tests/_shims/*`）已删除，测试现在 `node --test` 直跑 |
| 插件生命周期（激活 / 停用 / 重载） | 未覆盖 |
| `ctx.effect` / disposer 的真实调用时序 | 假 ctx 里是立即执行，真框架可能延后或批量 |

### B. 事件链路

| 项 | 说明 |
|---|---|
| `ctx.sessionProjections` 的真实事件积累 | 我 mock 了 `stateOf()` 返回值，**绕过了整个事件机制** |
| `tool/call` → 投影的 `apply()` 推导 | `identityFromEvent()` 只在源码层读过，未真跑 |
| `command/run` → 投影 | 同上 |
| resume / fork 后身份恢复 | 需真实 session log，未覆盖 |

### C. 真实调用形态

| 项 | 说明 |
|---|---|
| preset 工具 → 宿主方法的真实参数传递 | 我直接调 `host.writeEntry(...)`，**跳过了 preset 的 `callHost` 层** |
| Remote wire 层（参数名 / 序列化 / `arguments-invalid`） | 契约测试只做**静态三方差对**，未真跑 wire |
| `ctx.remote.$mount` 异步挂载 | API 层测试用 mock 契约对象，未真 $mount |

### D. 视觉与渲染

| 项 | 说明 |
|---|---|
| 控制台 `slot entry crashed` | 无浏览器控制 |
| 明暗主题可读性 | 同上 |
| 条目编辑 6 字段的实际交互 | 同上 |
| 渲染异常白屏 | 同上 |

### E. 数据与环境

| 项 | 说明 |
|---|---|
| 多进程并发写 | 只测了单进程 `Promise.all` |
| 跨平台路径（Linux / macOS） | 全在 Windows 上跑 |
| Node 版本差异 | 本地 v24.21.0；容器 v22.23.3 |
| 旧数据兼容（8 列 vs 9 列） | 容器里有 198 条 8 列旧记忆，**两代不兼容**，未做迁移 |

## 四、这些盲区能不能补？

**部分能，部分不能。**

| 盲区 | 能否用本地测试补 | 说明 |
|---|---|---|
| Config schema 契约 | ❌ 不能 | 需要真框架的 `resolveConfig` |
| 事件链路 / 投影 | ⚠️ 勉强 | 可以手造事件调 `apply(state, event)`，但那仍是"我理解的机制"，不是真机制 |
| preset → 宿主参数传递 | ✅ 能 | 可以在假 ctx 里跑完整 `callHost` 链 |
| Remote wire 层 | ❌ 不能 | 需要真 `$mount` |
| 视觉 | ❌ 不能 | 需要浏览器控制 |
| 多进程并发 | ✅ 能 | 起多个 node 进程 |
| 跨平台 | ⚠️ 需 CI | 本地只能跑 Windows |

**结论：有些盲区只能靠"装进真实环境跑一遍"来消除，这不是测试写得不够，是测法本身的天花板。**

## 五、写进流程的建议（给 Lead 参考）

1. **"本地全绿"必须配一句边界声明**：默认只代表"纯逻辑 + 直接调用路径"通过。
2. **凡是"框架在 apply 之前/之后做的动作"，本地测试一律视为未覆盖**（Config 校验、清单解析、依赖注入顺序）。
3. **凡是我 mock 掉的，都是盲区**。mock 越顺手，盲区越大 —— 这次 `stateOf: () => fakeValue` 就是典型。
4. **测试输入形态要覆盖"模型真的会怎么给"**，不是"我方便测就怎么给"。缺陷③ 就是我只测了"传全字段"。
5. **里程碑应包含"首次装进真实环境"这一步**，且预期它会暴露缺陷——**这不是返工，是流程应有的一环**。

## 六、当前已补的回归断言（只守形态，不守框架行为）

| 编号 | 断言 | 它能守住什么 | 它守不住什么 |
|---|---|---|---|
| **R9** | preset 不得导出无 `~standard` 的 Config | 防止再写出 `export const Config = {}` | 守不住"真 schema 是否 valid" |
| **R10** | `bindIdentity` 后 `identityOf` 立刻非 null | 防止"只 return 不存储" | 守不住"投影在真实事件下是否正确" |
| **R11** | 省略 项目/智能体 → **必须拒**（`PROJECT_EMPTY`/`AGENT_EMPTY`），报错须含「标签字典」「问用户」 | 防止默认值兜底被加回来 | 守不住"真实 preset 传参形态" |

> **这三条仍然跑在假 ctx 上。** 它们保证"代码形态不再写错"，
> **不保证"框架实际行为正确"**。真实容器验证不可被替代。
