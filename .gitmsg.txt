修 Remote 端点不生效：registerRemote 时机太早（fiber 未激活）

症状：客户端 $mount 成功但请求 404，且**重启多少次都一样**。

根因（cordis 源码 cordis/lib/index.js get/_getImpl）：
  get(name, strict = true) -> _getImpl(name, strict)
  _getImpl: if (strict && impl.fiber.state !== 2) return;   // state 必须 ACTIVE
  apply() 执行时本插件 fiber 还在加载（state !== 2），
  所以 ctx.get('typert') 返回 undefined，registerRemote 进来就 return，
  什么都没注册 —— 代码在文件里但执行时被静默跳过。

修法：
  registerRemote(ctx, service)   ->  ctx.inject(['typert'], (c) => registerRemote(c, service))
  用 ctx.inject 声明依赖，框架等 typert 就绪后再跑回调。

本轮累计修的 3 层问题：
  ① client: ctx.remote[NS] 被 cordis proxy 拦 -> nsRef + ctx.inject(['remote.tagMemory'])
  ② host:   ctx.typert.register({package,face,invocations}) 不是 Remote 注册入口
            -> 挂 typertRemote 绑定 + prototype 符号描述符 remote-methods
  ③ host:   普通对象字面量 prototype 是 Object.prototype，remoteMethods 读不到
            -> Object.setPrototypeOf(serviceObj, HostServiceProto)
  ④ host:   registerRemote 同步调用时 fiber 未激活 -> ctx.inject(['typert']) 延迟

容器验证：
  POST /api/tagMemory/getOverview -> HTTP 200 OK   ✅（原来的 404）
  GET  同路径 -> 404（正常，Remote 只吃 RPC POST）
  重启零激活报错                                    ✅
