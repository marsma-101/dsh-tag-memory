第5个缺陷：库格式不兼容时静默返回 total:0（host-dev 发现并修）

问题：
  listEntries / getOverview 把 readLibraryCsv 的 errors 丢弃，
  库格式不兼容（如 8 列旧库缺 自由标签）时返回 { ok:true, total:0 }
  -> UI 显示"暂无数据"，用户以为"记忆全没了"

total:0 有两种截然不同的含义：
  - 库真的是空的 -> 该去写记忆
  - 库格式不兼容、一行都没读进来 -> 该去处理格式
  UI 无法区分。这与前三处同一模式：把"读不到"伪装成"没有"。

修法：
  HEADER_MISSING 属致命 -> 走 fail() 并带 libraryIncompatible:true
  其余非致命（单行损坏）照常返回数据 + errors 供 UI 提示
  client 无需改代码，它已有"失败优先显示 message"的逻辑

容器内实测（8列旧库 vs 9列正常库对照）：
  8列: listEntries  ok=false code=LIBRARY_FORMAT_MISMATCH incompatible=true
        message: 表头缺少列：自由标签。必须 9 列齐全（顺序可变，列名必须对）
       getOverview  ok=false code=LIBRARY_FORMAT_MISMATCH
  9列: listEntries  ok=true total=1  / getOverview ok=true total=1 active=1
       正常路径完全不受影响

保留此修复（只影响错误路径，不增加正常路径复杂度）
