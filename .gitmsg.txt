修 dtm_merge 的「同号保留较新」是死代码

## dtm_merge 是什么

把另一份记忆库（CSV）合并进当前库，用于搬家前后、导出再导入、两台机器同步。
规则（《流程_整理》§二 L90）：编号唯一、同号保留较新、行只追加。

## 缺陷

原实现：
  const existing = byId.get(id);   // id 就是编号
  if (idNewerThan(rec['编号'], existing['编号'])) { 覆盖 }

但进到这个分支说明两条**编号完全相同** ——
idNewerThan("M-20261106-001", "M-20261106-001") 恒为 false。

「保留较新」是死代码，合并方的版本**永远被静默丢弃**，changed 恒为 0。

## 实测证据

造两份库：
  当前库  M-001 = "这是旧的内容"（时距1，观察）
  待合并  M-001 = "这是新的内容（应该覆盖旧版）"（时距3，稳定）

修复前：
  changed: 0
  合并后 M-001 = "这是旧的内容"        <- 新版被丢弃

修复后：
  changed: 1
  合并后 M-001 = "这是新的内容（应该覆盖旧版）"

## 修法

编号相同就用不了编号，改看条目自身状态。recordNewerThan() 优先级：
  ① 时距大者胜（时距=被召回次数，用得多的更贴合当下）
  ② 时距相同看稳定性：稳定(2) > 观察(1) > 易变(0)
  ③ 都一样则保留当前库（幂等，不折腾）
