修筛选失效 + 加沙箱内导出目录选择（用户报告的两个问题）

## 问题1：筛选是"摆设"（用户原话）

现象：选了下拉/填了标签，列表毫无变化。

根因：跨模块字段名漂移（教训2 的又一例）
  前端发  { shape, project, agent, status, tags }       英文
  宿主读  filter['形态'] / filter['项目'] / ...         中文

宿主读到的全是 undefined -> str() 成 '' -> 所有条件当"不限"
-> 返回全量 -> 用户看到"没反应"。**没有任何报错**。

修法：query 改成中文键，与宿主/CSV 列名/台账字段保持一致（零映射）。

实测：
  初始 177 -> 形态=事实 101 -> +标签PrivHub 11 -> 清除 177

## 问题2：希望能在沙箱内选备份/导出位置

原来 exportLibrary 只写死到 backupDir，且**根本没注册成 Remote 端点**
（所以 UI 上连按钮都没有）。

新增：
  · 宿主 listExportTargets() —— 会真的写临时文件探测写权限，
    只返回实测能写的目录（不给点下去必然失败的路径）
  · exportLibrary 注册成 Remote 端点
  · 设置页备份卡片加：导出位置下拉 + 导出按钮 + 刷新按钮

设计取舍：不让用户自由填路径。插件跑在沙箱/容器里，
宿主机路径（G:\...）在那侧根本不存在，填了也是 ENOENT。
宁可少给选项，也不给假选项。

实测：下拉 3 个目录，导出 177 条成功。

## 顺带消灭一个隐患：两份 REMOTE_SIGNATURES

加 exportLibrary 时端点一直 404，查出来 index.js 里有**两份**
REMOTE_SIGNATURES：一份在 createHostService（镜像层），
一份在 registerRemote（marker 层）。我只改了镜像层。

而 gateway 只从 marker 层的符号描述符发现端点 ——
镜像层有、marker 层没有 = 端点不存在 = 404，且**静默无报错**。

已提取成模块级唯一常量 `export const REMOTE_SIGNATURES`，
两个消费者都引用它。以后不可能再改错地方。
