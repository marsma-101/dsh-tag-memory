# 操作流程

四条主线：**写**、**捞**、**整理**、**升降级**。

机制原理见 `mechanism.md`；标签含义见 `tags.md`；本文是操作步骤。

---

## 一、写：追加一条记忆

### 步骤

```
① 判这是哪一类 → 写入路由：决策 / 交代 / 规矩 / 纠正 / 同意 / 无价值（entry-format.md 6.1）
                 它决定**写几条**——决策与交代各写 2 条（原文 + 总结），其余多半不写
② 判该不该记   → 写入四原则（entry-format.md 6.2）
③ 判类型       → 原文 / 记忆 / 固定（固定 = 本机硬信息）
④ 判深度       → 事件→情景；规律→语义；做法→程序（**仅 `类型=记忆`**）
⑤ 判稳定性     → 没意外会不会变？不会→稳定；拿不准→观察；会变→易变
⑥ 判距离       → 召回优先级：常驻 / 按需 / 深藏（`原文` 条一律 `深藏`）
⑦ 打辅助标签   → 最小充分（tags.md 第六节）
⑧ 追加到 CSV   → 有几条就调几次 append（同一批里 `原文` 的 `备注` 写配套 id）
```

### ⚠️ 写入闸门（硬规矩）

**AI 只提议，用户确认。**

要新增/修改记忆时：
- **新增**：可以直接追加（追加不改动已有数据，安全）
- **修改已有条目**：**先说改什么，等用户确认再动**

理由：本系统要求「AI 只提议，你确认」。改已有条目风险更高（可能改错、可能覆盖）。

### 怎么追加（用工具，别手写）

> **首选插件自带的 `memory_write` 工具**（自动取号 + 文件锁 + 字典校验 + 去重）：
> 参数直接填 `{"内容":"…","时间":"2026-10-13","环境":"…","原因":"…","类型":"记忆","深度":"语义","稳定性":"稳定","距离":"按需","角色":"萧潇","项目":"通用","依据":"推断"}`。
> **没有这个工具的宿主**才用下面的等价写法。

```javascript
// append.mjs —— 追加一条记忆（没有插件时的等价写法）
import { appendFileSync } from 'node:fs'
const F = process.env.DSH_HOME + '/tag-memory/store/memory.csv'   // 库在 <DSH_HOME>/tag-memory

function cell(v) {
  const s = v == null ? '' : String(v)
  return /[",\n\r]/.test(s) ? '"' + s.replace(/"/g, '""') + '"' : s
}

const row = {
  id: 'M-20261010-002',
  内容: '[通用] 示例\n说明文字',
  时间: '2026-10-10',
  环境: '什么条件下成立',
  原因: '为什么记',
  备注: '',
  稳定性: '稳定', 成熟度: '语义', 距离: '常驻',   // 成熟度 = 字典的 `深度`
  角色: '萧潇', 项目: '通用', 状态: '生效',
  关键词: 'a,b', 工具: '', 版本: '', 依据: '推断', 类型: '记忆',
}
// 迁移期：`成熟度` 列 = 字典的 `深度`；`类型` 列已在表头末尾（architecture.md §七）
const COLS = ['id','内容','时间','环境','原因','备注','稳定性','成熟度','距离','角色','项目','状态','关键词','工具','版本','依据','类型']
const line = COLS.map((c) => cell(row[c])).join(',') + '\n'
appendFileSync(F, line, 'utf8')
```

**id 怎么取**：`M-<当天日期>-<当天序号>`，序号看当天已有几条往后排。

## 二、捞：按标签召回

### 漏斗

```
① memory 入口（库里的 index.md）  → 常驻内容直接答，不动库
② 按标签筛 CSV             → 先窄后宽
③ 捞到后必判（时效/状态）
④ 依据记忆做决定 → 说出 id
```

### 一次取几条

**先报命中总数，再取前 3 条**：

| 步骤 | 做什么 |
|---|---|
| ① | 筛完先报**命中总数**（几条） |
| ② | 取前 3 条 |
| ③ | 还有没展开的 → 一句话带出「**另有 N 条命中未展开，要不要看**」 |

**不要一次全取**——全取既爆上下文，又稀释注意力。

### 怎么筛

> **首选插件自带的 `memory_recall` 工具**（完整读程序，支持 **与 / 或 / 非 / 留白 / 多值 / 区间** +
> `通用` 白名单 + 默认排除 `被取代/已归档` + **先报命中总数再取前 3**）：
> 参数写 `{"条件":"{\"项目\":\"通用\",\"深度\":[\"语义\",\"程序\"],\"稳定性\":\"稳定\"}","取几条":3}`。
> 用法与算子见 `architecture.md` §4.3。**没有这个工具的宿主**才用下面的简版。

```javascript
// query.mjs —— 按标签筛（简版）
import { readFileSync } from 'node:fs'
const text = readFileSync(process.env.DSH_HOME + '/tag-memory/store/memory.csv', 'utf8')

function parseCSV(t) {
  const rows = []; let row = [], cell = '', q = false
  for (let i = 0; i < t.length; i++) {
    const c = t[i]
    if (q) { if (c === '"') { if (t[i+1] === '"') { cell += '"'; i++ } else q = false } else cell += c }
    else if (c === '"') q = true
    else if (c === ',') { row.push(cell); cell = '' }
    else if (c === '\n') { row.push(cell); rows.push(row); row = []; cell = '' }
    else if (c !== '\r') cell += c
  }
  if (cell || row.length) { row.push(cell); rows.push(row) }
  return rows
}

const rows = parseCSV(text)
const H = rows[0]
const idx = (n) => H.indexOf(n)
const data = rows.slice(1).filter((r) => r[0])

// 筛选条件（按需改）
const want = { 稳定性: '稳定', 项目: 'PrivHub', 角色: '萧潇' }
const hit = data.filter((r) =>
  Object.entries(want).every(([k, v]) => r[idx(k)] === v) &&
  r[idx('状态')] !== '已归档' && r[idx('状态')] !== '被取代'
)

console.log(`命中 ${hit.length} 条，取前 3：`)
for (const r of hit.slice(0, 3)) {
  console.log(`\n[${r[idx('id')]}] ${r[idx('内容')]}`)
  console.log(`  环境: ${r[idx('环境')]}`)
  console.log(`  原因: ${r[idx('原因')]}`)
  console.log(`  稳定性: ${r[idx('稳定性')]}  距离: ${r[idx('距离')]}  状态: ${r[idx('状态')]}`)
}
```

### 捞到之后必做

| 看什么 | 怎么做 |
|---|---|
| `稳定性=稳定` | 直接用 |
| `稳定性=观察` | 简单核对 |
| `稳定性=易变` | **先核对当前情况**（涉及路径/版本/配置尤其） |
| `状态=被取代` | 去看取代它的那条 |
| `状态=已归档` | 默认不读 |

**显式引用**：依据记忆做决定时，说出条目 id。**记忆隐式影响判断 → 冲突不可见；显式引用 → 冲突自己浮出来。**

### 同轮内去重

召回时**多条说的是同一件事 → 只取一条，其余折叠**，并报出「另有 N 条同类」。

折叠**靠人读内容判断**——本系统没有哈希层，不用算指纹。

### 按时间窗筛

问句**明确指向某个时间段**（「上周那个」「10 月 7 号定的」）→ 在标签筛基础上**叠加 `时间` 列的范围筛**。

> **克制条款**：只是**顺口提到时间**（「今天在吗」「今晚做什么菜」）**不按时间筛**。

**这些都不按时间读**：

| 情况 | 例 |
|---|---|
| 日期范围 | 「10 月 7 号到 10 号」 |
| 超过三天的跨度 | 「这个月」「近一周」 |
| 未来日期 | 「下周三」 |
| 占位日期 | `9999-12-31` |

### 筛不到就说没找到（硬规矩）

按标签筛完 + 关键词搜完**仍无命中**：

| 做什么 | 怎么做 |
|---|---|
| **直接说** | 答「**记忆库里没有这条**」，并说明**筛了哪些标签** |
| **不许充数** | **不得拿常驻条目或其他条目顶替** |
| **记台账** | 这次失败记进 `<DSH_HOME>/tag-memory/store/misses.md`（召回失败台账） |

**理由**：**检索错记忆往往比不检索更糟**——拿一条不对的顶上，冲突反而看不见。

## 三、整理（用户发话时才做）

**触发**：用户说「整理一下记忆」。**不做定时任务**（DSH 的 schedule 只在会话内有效，进程关了就停）。

**⚠️ 整理前先自动备份**（不等用户开口）：在设置页点「立即备份」，或

```bash
node <插件目录>/scripts/backup.mjs --label "整理前"
```

整理会**改标签值、清空列、搬表头**——属于「改结构」，规矩是**先备后改**，反过来等于没备。
验不过就不动手（`backup.mjs` 会自行校验：记录数 + SHA-256 + 无 BOM，并登记水位）。

### 七步

```
① 翻本轮对话 + 近期记录，看哪些条目**被调用过**
     用对了 → 不动，可给 关键词 补一笔
② 看有没有「用户提过、但没想起来」的
     有 → **补标签**，写明"下次在什么情况下该用它"   ← 最有价值
③ 该升格：同类情景够 3 条 → 语义；多场景验证 → 程序
④ 该降：被取代/过时 → 改 状态
⑤ 标签乱长：没登记的 → 补进 tags.md 或清掉
⑥ 挑 `类型`：混在 `记忆` 里、其实是**本机硬信息**的（路径 / 装机 / 端口）挑成 `固定`；
     同一次输入的 `原文` 条与总结条按 `备注` 里的 `配套：` 配对——**冲突以 `原文` 为准**
⑦ 看**规矩**有没有漏：用户定过的长期禁令，`深度` 该是 `程序`、`距离` 该是 `常驻`——
     漏成 `语义`/`按需` 的，等于下次照样犯；补上
```

**第 ② 步是核心**：**召回失败一次，就补一次标签**。

### 为什么不做定时

DSH 的 `schedule` 是**会话内**的（`session-local`）：
- 提醒属于原会话，**进程关闭或会话变冷 → timer 停**
- **不支持 Cron**，不能写「每周日 03:00」

**所以整理靠用户发话**，这也符合用户「不要自动任务，容易失控」的要求。

## 四、升降级

**升**（方向：情景 → 语义 → 程序）：

```
① 聚类：同类情景归一堆
② 门槛：够多（参考 ≥3 个**独立场合**）才升
③ 提炼：概括成带条件的规则
④ 支撑：在 备注 里写明哪几次支撑了它，各是哪一次
```

> **一个案例不是规律，是噪声。** 不够门槛就不升。

**降**：改 `状态`（`被取代` / `已归档`），**不删行**——原文保留，追历史时还能看。

**升格是判断动作，不是自动动作**——先问用户。

---

## 五、冲突消解

新记忆与已有条目冲突时：

```
① 比来源可靠度 + 新鲜度 + 与其余知识的一致性
     ——**同一次输入的 `原文` 条与总结条之间，`原文` 优先**（原文是原话，总结是加工过的）
② 谁更可靠谁赢
③ 旧的【降权】——改 状态=被取代，不是抹掉
④ 新的在 备注 里写 取代：M-xxxx
```

**关键**：**更新的不一定更真**。旧记录降权而非删除，万一新证据后来被证伪，旧的还能恢复。

**三种「过期」要分清**：

| 类型 | 本质 | 怎么处理 |
|---|---|---|
| **作用域错配** | 横向：本来就不是这里的 | **不是过期**；先问一句 |
| **被取代** | 纵向：同一问题换了决定 | 旧条目标 `被取代` |
| **静默失效** | 外部变了，没人说 | 涉及易变对象，**用前先核对** |

## 六、查健康度

```javascript
// 统计各状态分布
const rows = parseCSV(readFileSync(process.env.DSH_HOME + '/tag-memory/store/memory.csv','utf8'))
const H = rows[0], idx = (n) => H.indexOf(n)
const data = rows.slice(1).filter(r => r[0])
console.log('总数:', data.length)
console.log('生效:', data.filter(r=>r[idx('状态')]==='生效').length)
console.log('被取代:', data.filter(r=>r[idx('状态')]==='被取代').length)
console.log('已归档:', data.filter(r=>r[idx('状态')]==='已归档').length)
// 列出用过的标签
// 迁移期：`成熟度` 列 = 字典的 `深度`；表头迁移后改回 `深度` 并加 `类型`
for (const col of ['稳定性','成熟度','距离','项目','角色','工具','依据']) {
  const vals = [...new Set(data.map(r=>r[idx(col)]).filter(Boolean))]
  console.log(`${col}: ${vals.join(', ')}`)
}
```

**定期检查**：标签有没有跑出 `tags.md` 的登记？有没有该升格的情景堆积？有没有冲突未消解？

## 七、降级模式（宿主没有 shell）

CSV 是**纯文本**，任何能读文件的宿主都能用：

| 档 | 宿主能力 | 怎么查 |
|---|---|---|
| A | 有脚本执行 | 照本文走 |
| B | 只能读文件 | 用宿主自己的搜索功能搜标签 |
| C | 只能读文本 | 整文件读入（条数多了费 token，此时应精简） |

**降级不改变规则**——标签含义、列结构、四原则完全一致，只是检索手段退化。
