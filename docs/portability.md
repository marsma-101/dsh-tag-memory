# 移植说明（装到别的宿主机）

> **本插件不装在有 nowen-note 的机器上。** 它是给**没有 nowen-note 的机器**用的降级版。
> 装了 nowen-note 的机器继续用原来那套（nowen-note 记忆库 + MEMORY.md 手边层），不要两套并存。

## 一、为什么这版能搬

| | 原 nowen-note 版 | 本版 |
|---|---|---|
| 依赖 | `localhost:3001` 常驻服务 + MCP 令牌 | **无** |
| 数据形态 | 服务端 SQLite，靠 API 读写 | 两个纯文本文件 |
| 换机器 | 要重装服务、重建令牌、重导数据 | **拷目录即可** |
| 能读的宿主 | 只有能连 MCP 的 | 任何能读文件的 |

## 二、怎么装

1. 把整个插件包（`dsh-tag-memory/` 目录，或 zip 解压后）拷到目标宿主机。
2. 装进该宿主的**插件目录**：

   | 宿主 | 典型插件目录 |
   |---|---|
   | DeepSeek Harness | `~/.dsh/profiles/<profile>/node_modules/`（或该宿主文档里的插件安装位置） |
   | Claude Code | `~/.claude/skills/`（那是它自己的技能机制，与本插件无关） |
   | 其他 | 该宿主文档里「plugin / extension」那一节 |

3. 确认 `package.json` 与 `index.js` 在目录**根层**（不要多套一层文件夹）。
4. **库不在插件目录里**——它在 `<DSH_HOME>/tag-memory`。第一次写记忆时插件会自己建（见 `storage-init.md`）。
5. 起一个新会话，说「记住 XXX」，看 `<DSH_HOME>/tag-memory/store/memory.csv` 有没有生成。

> **注意**：目标宿主的插件目录如果**不可写**，装不进去。
> 本机实测过这种拒绝（`file access denied under workspace-write mode`）。
> 处理办法见 `storage-init.md` 第三节。

## 三、空库怎么起

**正常情况下不用手动起**——插件第一次写记忆时会自检并创建库（见 `storage-init.md`）。

若要手动建，把插件自带的 `lib/engine/templates/memory.csv`（只有表头）复制成 `<DSH_HOME>/tag-memory/store/memory.csv` 即可。

**⚠️ 不要手写 CSV 数据行**——内容含逗号/引号/换行时极易错列。**用脚本追加**（见 `workflow.md` 第一节）。

### ⚠️ 写文件的坑（实测）

**Windows PowerShell 5.1 的 `-Encoding UTF8` 会写出带 BOM 的文件**，而且 `-Encoding utf8NoBOM` 这个参数**在 5.1 上根本不存在**（那是 PowerShell 7 才有的）。

**BOM 会让 CSV 第一格解析失败**（第一个字段名前面多了三个字节）。所以：

```powershell
$enc = New-Object System.Text.UTF8Encoding($false)   # $false = 不写 BOM
[System.IO.File]::AppendAllText($path, $line + "`n", $enc)
```

**更省事的办法**：用 `node` 写，node 默认不写 BOM。

```bash
node -e "require('fs').appendFileSync(process.argv[2], process.argv[1] + '\n', 'utf8')" '<那行 CSV>' '<DSH_HOME>/tag-memory/store/memory.csv'
```

**验一下有没有踩坑**（头三字节应是你第一个字段的开头，不该是 `239,187,191`）：

```powershell
[System.IO.File]::ReadAllBytes($path)[0..2] -join ','
```

> 这条是 2026-10-09 在本机实测出来的：当时按 `-Encoding utf8NoBOM` 写，参数直接报错、文件根本没生成。**别照抄网上 PowerShell 7 的写法。**


## 四、三档能力降级

目标宿主机能力不同，按档用：

| 档 | 宿主能力 | 怎么查 |
|---|---|---|
| **A 完整** | 有脚本执行 / 文件读写 | 照 `workflow.md` 走，用脚本按标签筛 |
| **B 半自动** | 只能读文件，不能跑命令 | 读 `index.md` 定位 → 打开 `memory.csv`，**用宿主自己的搜索功能**搜 `稳定性=稳定` 这类值 |
| **C 最差** | 只能读文本、无搜索 | 读 `index.md` 的常驻规则；需要正文时**整文件读入**（条数多了费 token，此时应精简或分批读） |

**降级不改变规则**——各维度的含义、列结构、四原则完全一致，只是检索手段退化。

## 五、跨宿主共用同一个库

如果两台机器要共用一份记忆：

- **放同步盘**（网盘 / 局域网共享 / Git 仓库），两边指同一个库目录（`<DSH_HOME>/tag-memory`）。
- **CSV 追加式写入天然适合同步**：一行独立，冲突面小。
- **风险**：两边同时写会冲突。规矩是——**同一时间只在一台机器上写**，另一台只读；或者各写各的，定期合并。
- **合并办法**：把两个 `memory.csv` 的数据行拼起来，按 `id` 去重
  （`id` 带日期+序号，跨机器可能撞号，撞了就把一台的序号段整体偏移）。
  **合并时用 CSV 解析器，不要用文本拼接**——多行单元格会被拆散。

## 六、跨机合并与脱敏导出（**用户要求时才做**）

> 本节原来在旧技能包里是 `SKILL.md` 的第五节，2026-10-13 挪出来，现已归入本插件 `docs/`。
> §五 讲的是「两台机器共用一份库」；本节讲的是「把另一台机器的库**并进来**」和「把库**发出去**」。

### 6.1 合并流程

```
① 用户提供另一台机器的记忆库（打包的库目录或 zip）
② 解压到临时位置，**不要直接覆盖本机库目录**
③ 先备份本机库里的 memory.csv（带日期）
④ 逐条比对：id 撞号怎么处理 → 见 6.2
⑤ 全部合并完 → **先整理和推理，再报数**（见 6.4）
```

### 6.2 id 撞号怎么处理（按内容判，不看 id）

```
撞号了 → 先比内容
   ├─ 内容相同 → **直接跳过**（同一条记忆，不重复记）
   └─ 内容不同 → **改并入条目的编号**，作为新内容追加
```

**要点**：**判断依据是「内容」不是「id」**。id 只是编号，两台机器各编各的，
**同一个号下完全可能是两回事**——不能因为 id 相同就以为重复。

### 6.3 合并铁律

| 铁律 | 说明 |
|---|---|
| **先备份** | 合并前把本机库里的 `memory.csv` 复制一份带日期的 |
| **只追加，不重写** | 见 `multi-agent.md` 第〇节 |
| **不删任何条目** | 重复的也标 `已归档` 而非删除 |
| **id 撞号按内容判** | 见 6.2 |

### 6.4 ⭐ 报数前必做：先整理和推理，再报数

**合并不完就报数是不行的**——那只是「搬了多少条」，不是「记忆库变成了什么样」。

```
合并完 → ① 整理（查重、标签准确性检查、冲突处理）
       → ② 推理（跨条目归纳，能不能得出新原理）
       → ③ **然后**才报数
```

**报数要报这些**（不是只报条数）：

| 报什么 | 例 |
|---|---|
| 新增几条 | 12 条 |
| 重复跳过几条 | 3 条（内容相同）|
| id 撞号改号几条 | 2 条 |
| **改标签几条、为什么** | 5 条——其中 3 条维度判错已修，2 条语义重复已补标签区分 |
| **冲突几条、怎么处理** | 1 条——两台机器记了同一件事的不同版本，已各打 `版本` 标签 |
| **归纳出什么** | 发现「XX」原则在两边都出现过 → 该升级 |

### 6.5 语义相同/相似、但标签不一致 → 从标签上区分

**这是合并里唯一容易出事的地方**：两条说的是同一件事，但标签打得不一样，
**调用时不知道该用哪条**。

**处理**：不是删掉一条，而是**补标签把适用条件分开**。

| 情况 | 怎么区分 |
|---|---|
| **作用域不同**（一个通用、一个项目专属）| `项目` 一个填 `通用`，一个填项目名 |
| **版本不同** | 各打 `版本=v1` / `版本=v2` |
| **深度不同**（一个是事件、一个是规律）| `深度` 一个 `情景`、一个 `语义` |
| **稳定性不同**（一个易变、一个稳定）| `稳定性` 分开打 |
| **就是重复** | 合并成一条，旧的标 `状态=已归档`，`备注` 写明并入哪条 |

**判据**：**能不能说清「什么情况下用哪条」？** 说得出 → 两条都留、补标签；说不出 → 是重复，合并。
详见 `conflict.md`。

### 6.6 ⭐ 导出记忆库包时的**脱敏规则**（2026-10-12 定）

**记忆库要发给别的机器时，必须先过滤「本机专属内容」**——否则等于把本机的钥匙和地址簿交出去。

**两档处理，不能一刀切**：

| 档 | 判据 | 处理 |
|---|---|---|
| **A 本机专属** | **条目的核心价值就是「在那台机器上的位置」** | **整条排除**，不进包 |
| **B 路径只是附带** | 条目讲的是知识/方法，路径只是举例 | **通用化**：把具体路径换成占位符 |

#### A 档：必须排除（整条不进包）

| 类型 | 例 |
|---|---|
| **凭据 / 密钥 / 令牌的位置** | 「XX 令牌存于 `<用户目录>\.agents\xx.env`」|
| **本机专有的程序绝对路径** | 「python 装在 `D:\Program Files\Python312`」|
| **本机专有的配置目录** | 「配置在 `C:\Users\<用户名>\AppData\...`」|
| **本机专有的端口 / PID / 会话号** | 「服务跑在 30801」|
| **个人身份信息** | 真名、邮箱、账号、AppID |

**判据一句话**：**这条离开这台机器还有意义吗？没有 → 排除。**

#### B 档：通用化（保留条目，替换路径）

| 原文 | 改成 |
|---|---|
| `C:\Users\Administrator\.dsh\skills\X` | `<DSH_HOME>\skills\X` |
| `D:\Program Files\Python312\python.exe` | `<本机 Python 路径>` |
| `G:\AI_treaning\...` | `<工作区>\...` |
| 具体用户名 | `<用户名>` |

**判据**：**条目讲的是知识，路径只是举例 → 通用化后保留。**

#### 排除/替换后要在备注里留痕

```
备注 = 原备注 + 「｜导出时已脱敏：<做了什么>」
```

**为什么要留痕**：不然合并到另一台后，看到内容被改过却不知为何。

#### 导出包要带一份「排除清单」

**报给用户**（不是静默处理）：

| 报什么 | 例 |
|---|---|
| 排除几条、为什么 | 2 条——含本机凭据路径 / 本机专有程序路径 |
| 通用化几条 | 6 条——路径换成占位符 |
| 剩余几条进包 | 115 条 |

**⚠️ 排除的条目只在本包中不出现，本机库照常保留**——不是删除。

## 七、和 nowen-note 版共存

**前提**：不在同一台机器上混用。

| | nowen-note 版 | 本版（CSV） |
|---|---|---|
| 存储 | nowen-note 服务 | 本地 `<DSH_HOME>/tag-memory/store/memory.csv` |
| 依赖 | 要跑服务 + MCP | **无** |

**搬运注意**：**两边的标签体系已不同**——
nowen-note 版用的是「角色/项目/类型」前缀标签；本版用 **`类型` + 三个维度**。
搬的时候要**映射**，不是直接抄：

| nowen-note 版 | 本版 |
|---|---|
| 无（原「层」） | `类型` = 原文 / 记忆 / 固定 |
| `类型:决策/教训/偏好/进度` | `深度` = 情景 / 语义 / 程序；`稳定性` = 稳定 / 观察 / 易变 |
| 无 | `距离` = 常驻 / 按需 / 深藏 |

**不要**让两边同时当权威。定一个主，另一个只做镜像。

## 八、备份

只要三个文件：

```
<DSH_HOME>/tag-memory/store/index.md      记忆入口（指针）
<DSH_HOME>/tag-memory/store/memory.csv    记忆库（一行一条）
<DSH_HOME>/tag-memory/store/backup.json   备份配置
```

**一键备**（推荐）：在设置页点「立即备份」，或 `node <插件目录>/scripts/backup.mjs [--label 说明]`
它自动：复制这些文件 → **校验（记录数 + SHA-256 + 无 BOM）** → 更新 `backup.json` 水位 → 按 `keepCopies` 轮转旧备份。
**备份位置可配**：改库里的 `backup.json` 的 `backupDir` 即可（**没有默认目录**，必须显式设一个绝对路径）。

**手动备**：把这些**复制**到 `backupDir`（库外的一个目录），文件名带日期：

```
<backupDir>/index-20261012.md
<backupDir>/memory-20261012.csv
<backupDir>/backup-20261012.json
```

**什么时候备**（到点就备，不等用户开口）：

- **距上次备份超过 `staleDays` 天**（默认 30）
- **自上次备份起新增 ≥ 20 条**（`promptEveryEntries`）
- **改表头 / 改列结构之前**——**先备后改**，反过来等于没备
- 用户说「整理一下记忆」、升级插件、跨机合并之前

**备完必须核对**（拷完不算完）：

- **行数一致**：用 **CSV 解析器数记录数**比对原件与副本，**不要数换行**——
  单元格里有换行，物理行数 ≠ 条目数（2026-10-12 实测：515 物理行只有 129 条）。
- **字节数与 SHA-256 一致**，副本**无 BOM**（头三字节不是 `239,187,191`）。
- 验不过就别更新 `lastBackupAt`。

详细步骤与现成脚本见 `backup.md` 第三节。

- **不要**把备份和原件放同一个目录被同一个同步任务覆盖。

## 九、排障

| 症状 | 原因 | 处理 |
|---|---|---|
| 标签筛不出来 | 值里有多余空格 / 大小写不一致 | 用**等号全匹配**，值不要带空格 |
| 筛出多余条目 | 用了「包含」匹配 | `稳定` 会误命中 `稳定X`，必须全匹配 |
| CSV 错列 | 内容含逗号但没包引号 | 整格包双引号；**用脚本写，别手写** |
| 多行内容被拆散 | 合并时用了文本拼接 | **用 CSV 解析器**合并 |
| 第一条解析失败 | 文件有 BOM | 重写为无 BOM |
| 中文显示乱码 | 宿主输出编码不是 UTF-8 | 文件本身没问题，是显示层；用 UTF-8 读 |
| 库文件越来越大 | 只增不减 | 已归档条目可剪到 `memory-archive-<年月>.csv`（**只剪不删**） |
