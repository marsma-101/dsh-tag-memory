# 架构总纲

> **本文件讲这套记忆系统的「是什么、怎么转」**：作用、架构、要求、模式。
> 细则：字典 → `tags.md`；流程 → `workflow.md`；列 → `entry-format.md`；理论背景 → `mechanism.md`。
> 读者：用本插件的智能体 + 维护本插件的人。

---

## 一、作用：治主流记忆系统的三个通病

| 通病 | 本系统的解法 |
|---|---|
| 存太多 → 一次召回太多 → **记忆混乱 / 上下文污染** | **多维标签同时筛选**，只取命中的几条 |
| 召回太多 → **占 token** | 先报命中总数，再取前 3；常驻设硬上限 |
| 存了却 **没被召回**（存在但读不出来） | 字典进「每轮注入层」+ 确定性的筛选程序 |

**核心主张**：**存得多 ≠ 每次都要调用。** 靠"给每条打多维标签"，把「**全量存储**」和「**精确取用**」分开——甚至可以连原文一起存下。

---

## 二、架构：一个库 · 三条规则 · 一个字典 · 两种程序

```
        ┌─ 一个库 ── <DSH_HOME>/tag-memory/store/memory.csv（一行一条，只追加）
        │
一套系统 ├─ 三条规则 ── 写 / 读 / 整理
        │
        ├─ 一个字典 ── docs/tags.md（存和读都照它）
        │
        └─ 两种程序 ── 写程序（编号+入库）/ 读程序（筛选+喂回）

附属：备份程序、注入片段（把字典塞进每轮上下文）
```

**分工铁律**：

- **模型**：判断——这条该不该记、话题映射到哪几个维度、每维取什么值
- **程序**：执行——编号、追加、筛选、返回
- **序号、扫库这类机械活，模型一律不碰**

---

## 三、要求（边界，不能动）

| 边界 | 说明 |
|---|---|
| **不引外部** | 不引 API / 向量 / 辅助模型 / key / 网络依赖 |
| **一套逻辑一个库** | 一份规则、一个 store、同一套逻辑管存/读/整理；不拆多引擎、不搞多套并存 |
| **只追加** | 平时只追加；**改已有条目先问用户** |
| **明文凭据只记位置** | 不写内容 |
| **可搬** | 纯文本 CSV，整包可移 |

## 四、模式：多维标签怎么转

### 4.1 标签 = 维度

**一列 = 一个维度**，每个维度是**取值有界的下拉**（不是自由文本）。
写记忆时逐维填；**定不了就留白**，别瞎编。

### 4.2 两段式：模型判断，程序执行

```
① 模型：读字典 → 定"本轮从哪几维筛、每维什么条件"
② 程序：照条件扫库 → 返回命中（先报总数，再取前 3）
③ 模型：按命中回答，显式引用 id
```

**模型不碰 CSV。**

### 4.3 条件语言（读程序必须支持）

**与 / 或 / 非 / 留白 / 多值 / 区间**。

> 现状只支持「全等值 AND」——这正是"多维退化成一维"的根，必须补。

### 4.4 白名单与黑名单

| 值 | 语义 |
|---|---|
| `通用` | **白名单**：任何取值下都成立（不受该维限制）|
| 留白 | **黑名单**：还没判，不参与常规召回（除非专门查留白）|

> **例外**：有些维的留白本身是**有效值**（如 `深度` 在 `类型≠记忆` 时留白），不套黑名单。

### 4.5 激活规则

`深度` **仅当 `类型=记忆` 时填**；`类型=原文 / 固定` 时 `深度` 留白。
（理由：原文的原始内容已在 `类型` 里体现，不再走形态分层。）

### 4.6 `距离` = 召回优先级

`常驻` = **每轮优先提请**（候选第一位），**仍受其他维约束**——别的维能把它筛下去（如 `项目`）。
真正"每轮必进上下文" = `常驻` **且** 其他维皆不限。

## 五、维度总表

| 维度 | 取值 | 管什么 | 备注 |
|---|---|---|---|
| `类型` | 原文 / 记忆 / 固定 | **主开关** | 原文·固定 不启用 `深度` |
| `深度` | 情景 / 语义 / 程序 | 记忆形态 | 仅 `类型=记忆`；有升降级 |
| `稳定性` | 稳定 / 观察 / 易变 | 用时该不该核对 | |
| `距离` | 常驻 / 按需 / 深藏 | 召回优先级 | `常驻` 受其他维约束 |
| `项目` | 通用 / 项目名 | 哪儿的事 | `通用`=白名单 |
| `工具` | 工具名 | 涉及哪个工具 | 可空 |
| `作用` | 领域（音频/视频/前端…）| 干什么用的 | ⚠️ 待定 |
| `角色` | 谁写入的 | 溯源（工作环境）| |
| `依据` | 原话 / 推断 / 外部 | 这话谁说的 | **必填** |
| `状态` | 生效 / 被取代 / 已归档 | 还有效吗 | |
| `版本` | v1 / v2 | 冲突区分 | 暂空是对的 |
| `关键词` | 自由 | 兜底检索 | |
| `时间` | 日期 | 时间窗 | |

## 六、跟「四层记忆架构」的关系

四层（工作 / 情景 / 语义 / 程序）落进**两根轴**，不重复：

| 四层的层 | 归谁 |
|---|---|
| 工作记忆（进不进上下文）| `距离` |
| 情景 / 语义 / 程序 | `深度` |

`距离` + `深度` 合起来 = 完整四层。

## 七、存储形态与迁移

现行 CSV 表头（**21 列**，含 0.3.0 新增的 强度/最后强化/已验证项目/使用次数；17 列老库启动时自动迁移）与本总纲的差距：

1. ~~**新增 `类型`**（原文 / 记忆 / 固定）~~ —— **2026-10-15 已落**（表头末尾加列，
   存量行一律回填 `记忆`：它们本就是「提炼的结论」；`固定` / `原文` 留给整理时逐条挑）。
   回填而**不是留空**，是因为留白=黑名单——留空的话一按 `类型` 筛就把老条目全筛没了。
2. `成熟度` → **`深度`**（改名，含义不变：情景 / 语义 / 程序）——**仍未做**
3. `稳定性` 取值改为 **稳定 / 观察 / 易变**（原：固定 / 稳定 / 易变）——**仍未做**

**迁移规矩**：先在设置页点「立即备份」（或 `node <插件目录>/scripts/backup.mjs --label "..."`），再动结构；验不过就不动手。
余下两处（`成熟度`→`深度`、`稳定性` 取值）交给**整理流程**统一处理。
