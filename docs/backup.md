# 备份规则

> **定位：兜底，不是保命项。**
> 规则了更好的办法——**发布包不带 `store/`**，写入时自检补齐（见 `storage-init.md`）。
> 所以「覆盖升级盖掉记忆」这条主要风险已经堵住了，备份现在防的是剩下几种：
> 删目录重解压、误删、磁盘坏、格式改坏。
>
> **节奏**：地址设好之后，**写它不算对外操作，到点直接备**（第二节两个硬触发点）。
> 备一次就三个文件的拷贝，成本极低，不必省。

## 一、备份到哪：**没有默认目录，地址必须显式给**

`backupDir` **没有默认值**。空字符串就是「没设地址」，**不许拿一个内置目录顶上**：
备份地址是「这台机器上这份记忆库的档案存在哪」，猜错了等于没有档案。

```json
{
  "backupDir": "",
  "lastBackupAt": "",
  "promptEveryEntries": 20,
  "staleDays": 30,
  "keepCopies": 10
}
```

| 字段 | 含义 |
|---|---|
| `backupDir` | **备份文件夹绝对路径**。**空 = 没设地址**，不是「用默认目录」 |
| `lastBackupAt` | 上次备份时间（ISO 8601）。**每次备份后必须更新** |
| `promptEveryEntries` | 自上次备份起新增多少条**就备份**（默认 20） |
| `staleDays` | 距上次备份超过多少天**就备份**（默认 30） |
| `keepCopies` | 备份目录里保留最近几份（默认 10），超出的最旧的删掉 |

### 没设地址时怎么办：**把你带到设置地址那一步，别弹提醒**

| 入口 | 没设地址时的行为 |
|---|---|
| DSH 界面「记忆」页 | 点「立即备份」→ **直接展开「设置备份地址」那块面板**（跟点那颗按钮一模一样），不是弹一句「请先设置地址」 |
| 命令行 | `node <插件目录>/scripts/backup.mjs` → 报错退出，并告诉你先用 `--dir <绝对路径>` 或去界面设地址 |
| 智能体 | **先想办法把地址定下来**（问用户，或挑一个明显的备份盘/目录），定完立刻备一次。**不要因为「没地址」就不备份了**——那正是下面这个教训 |

> 2026-10-12 实测教训：`backupDir` 是空串时，**备份从来没跑过**——124 条记忆零备份。
> **「等用户指定目录」等于「永不备份」。**
> 所以现在反过来：没地址不是「跳过」，而是**一个必须马上处理掉的状态**——
> 界面上它就是一颗显眼的按钮，到点（或人一点）就落到「设地址」那一步。

### 地址是**弹框选的**，不是手打的

界面上的「设置备份地址…」按钮会**弹系统的「选择文件夹」框**，不用手打路径。

- 用的是 **DSH 自己的那道门**：客户端 `ctx.uiWorkspace.pickDirectory()`——
  也就是开新会话选工作区时弹的**同一个框**。native（系统选择框）/ 内建浏览两种后端它自己适配，
  取消、窗口前台激活这些它也处理好了。
- **别自己去 spawn 进程弹框。** 试过的坑：服务端拉 `powershell.exe` 弹
  `System.Windows.Forms.FolderBrowserDialog`，**框能建出来但开在别的窗口后面**，等于弹不出来。
  原因是 Windows 只把前台激活权给前台进程——DSH 的原生选择框自己在 `Show` 之前
  合成了一次 Alt 按键才抢到（见 `dsh-host-directory-picker-native` 的实现）。
- **两级兜底**：拿不到 `uiWorkspace`、或它没有原生选择能力 → 退回**内建目录浏览**
  （`uiWorkspace.listDirectory()` 给的一层：面包屑 + 子目录 + 「就选这个目录」）；
  连这个也没有 → 输入框还在，手填绝对路径。
- **只选不存**：选完只是把路径填回输入框，要再点一下「存下并立刻备份」才落笔、才写库里的 `backup.json`。

命令行没有弹框这条路（`node <插件目录>/scripts/backup.mjs` 是给脚本/智能体用的），照旧 `--dir` 或先在界面里设好。

### 地址怎么校验

- 必须是**绝对路径**（相对路径直接拒）。
- 不存在就**先建**（`mkdir -p`）；建不了或不可写 → 报错，**不落配置**。
- 不能就是 `store/` 本身（会自己盖自己）。
- **两个引擎别共用一个备份目录**：文件名按时间戳，但轮转（保留最近 `keepCopies` 份）是**按目录**数的，
  两套库共享一个目录会互相把对方的备份删掉。真共用了，就给这套库换一个单独的地址。

## 二、什么时候备份

### 两个硬触发点（**到了就备，不问**）

| # | 触发点 | 为什么是它 |
|---|---|---|
| ① | **距 `lastBackupAt` 超过 `staleDays` 天**（默认 30） | 时间兜底。就算一直不写新条目，配置和索引也在变 |
| ② | **自上次备份起新增条目 ≥ `promptEveryEntries`（默认 20）** | 条数是真正的风险敞口——20 条是「丢一次会疼」的量 |

**怎么算「新增几条」**：数 `memory.csv` 里 `时间` 晚于 `lastBackupAt` 的条目。
**懒得算就按条数估**：上次备份时 129 条 → 现在 150 条，就是新增 21 条，该备了。

**为什么把「提醒」改成「直接备」**：旧规矩是「提醒用户，不擅自备」。
实测结果——`promptEveryEntries: 20` 配了，**从没触发过，124 条零备份**。
提醒没人接就等于没有。

**只提醒、不动手的情况只剩一种**：地址已经设成了**别人的**目录（比如寄到 U 盘或网络盘），
写那个目录才算对外操作 → 那时提醒，等用户点头。

### 顺手触发（不单独为它开一次）

| 触发 | 动作 |
|---|---|
| 用户说「备份一下」 | 立刻备 |
| 用户说「收拾记忆 / 整理一下记忆」 | **整理前先备**（要动标签列、要改表头，必须留底） |
| **改表头或列结构之前** | **先备**——这是唯一「改坏了不可逆」的操作 |
| **升级／替换插件之前** | 先备（稳妥起见，虽然发布包已不带 store/） |
| 跨机合并之前 | 先备（`docs/portability.md` 第六节已写） |

**顺序铁律**：**先备，后改。** 反过来就等于没备。

**别频繁备**：一天一份、同日覆盖。同一件事不要连备三次。

## 三、怎么备份

**别手搓**：在设置页点「立即备份」，或跑 `node <插件目录>/scripts/backup.mjs`——两边是同一条代码路径
（插件内 `lib/engine/backup.mjs`），自带校验、水位、轮转。下面只是把它的行为写清楚。

把 `store/` 里三个文件复制到 `backupDir`，**文件名带日期时间**：

```
<backupDir>/
├── index-20261014-084203.md
├── memory-20261014-084203.csv
└── backup-20261014-084203.json
```

**戳到秒**（`YYYYMMDD-HHMMSS`，老备份是 `YYYYMMDD-HHMM`，轮转两种都认）。
到秒不是洁癖：恢复的第一步是「先把现在这一版留档」，紧接着才换文件——
只到分钟的话这两件事必然撞同名，留档会**把你要恢复的那一份覆盖掉**。

**绝不覆盖已有内容**：如果那个戳上已经有一个**内容不一样**的同名文件，这一份**自动往后挪一秒**
再试（最多 5 秒），并在结果、日志和界面提示里说明。挪不动才报错。

**只复制，不动原件**：绝不移动、绝不删除、绝不覆盖 `store/` 里任何文件。

**Windows PowerShell 5.1 示例**（注意别用 `-Encoding UTF8`，见 `portability.md`）：

```bash
# 一次备份：备份地址从 <DSH_HOME>/tag-memory/backup.json 读（没设就报错，让你去设）
node <插件目录>/scripts/backup.mjs --label "整理前"

# 只是想看一眼现状（不写任何东西）
node <插件目录>/scripts/backup.mjs --status

# 这一次临时换个地址（不写回配置）
node <插件目录>/scripts/backup.mjs --dir D:\backup\记忆库 --label "寄到 U 盘"
```

**别用 PowerShell 手搓**：编码坑（见 `portability.md`）会把你原本没 BOM 的 CSV 写出 BOM，
校验那一关过不去——`backup.mjs` 会把「副本无 BOM」当硬条件。

**备份后**：把 `lastBackupAt` 更新为当前时间。

### ⭐ 拷完不算完——必须验四样

**「文件在那儿」不等于「备份可用」。** 每次备份后跑一遍：

| # | 验什么 | 怎么验 | 过关线 |
|---|---|---|---|
| ① | **字节数一致** | 比源与副本的 `Length` | 两数相等 |
| ② | **哈希一致** | 比 SHA-256 | 完全相等（最硬的一条） |
| ③ | **能解析、行数一致** | **用 CSV 解析器数记录数**（不是数 `\n`！） | 数据行数 == 原件数据行数 |
| ④ | **没有 BOM** | 读头三字节 | 不等于 `239,187,191` |

**⚠️ 别用「数换行」验行数**——`memory.csv` 的单元格里带换行，
**物理行数 ≠ 条目数**。2026-10-12 实测：原件物理 515 行，实际只有 **129 条数据**（123 条内容含换行）。
**必须用 CSV 解析器（RFC4180 引号规则）数记录数**，或者数「以 `M-` 开头的行」当交叉验证。

**验行数的一段现成脚本**（把两个路径都传进去对比）：

```bash
node -e "const fs=require('fs');for(const p of process.argv.slice(1)){const t=fs.readFileSync(p,'utf8');let r=[],c=[],f='',q=0;for(let i=0;i<t.length;i++){const ch=t[i];if(q){if(ch==='\"'){if(t[i+1]==='\"'){f+='\"';i++}else q=0}else f+=ch}else if(ch==='\"')q=1;else if(ch===','){c.push(f);f=''}else if(ch==='\n'){c.push(f);r.push(c);c=[];f=''}else if(ch!=='\r')f+=ch}if(f!==''||c.length){c.push(f);r.push(c)}const n=r.filter(x=>!(x.length===1&&x[0]===''));console.log(p,'bytes',fs.statSync(p).size,'data',n.length-1,'cols',[...new Set(n.map(x=>x.length))].join('|'))}" 'store/memory.csv' 'backups/memory-<日期>.csv'
```

两边打印的 `bytes` 和 `data` 必须一样，`cols` 必须是单个值（说明没串列）—— 路径换成库里的 `memory.csv` 与 `backupDir` 里的副本。原文里的 `'store/memory.csv' 'backups/memory-<日期>.csv'` 即这两个位置。

**验不过就别更新 `lastBackupAt`**——那是自欺。

**收据留痕**（借鉴自参考项目的收据驱动做法，只取这一层，不引复杂度）：
在 `backupDir` 里留一行 `last-backup.log`，写明**这次备的是哪个版本**：

```
2026-10-12T11:39:12  backup 20261012-113912  条目=129  整理前
2026-10-14T09:10:44  restore 20261014-084203  条目=130  恢复前留档=20261014-091044
```

一行的四个字段：**真实时间 → 动作（backup/restore）→ 戳 → 条目数 → 说明（随便写）**。
恢复那行多一个「恢复前留档=」，指向它自己留的那一份。

**为什么记条目数**：日后要恢复时，**能说清恢复的是哪一版**，而不是「大概是那天的」。

## 四、清理旧备份（轮转）

备份目录里超过 `keepCopies` 份时，**删最旧的**：

- 只认 `memory-<戳>.csv` 这个格式来数份数（戳是 `YYYYMMDD-HHMM` 或 `YYYYMMDD-HHMMSS`）；
  删的时候把**同戳的 `index-*.md` 与 `backup-*.json` 一起带走**，别留孤儿。
- **别碰目录里其他东西**：`last-backup.log`、别人的备份、别的留底目录（例 `plugin-pre-v2-<日期>/`）都不删。
- 先备后删，顺序不能反。

## 五、从备份恢复：**整体替换**

**恢复是「把整库换成那一版」，不是「往上面补」。** 目的就是「把搞乱的那一版换掉」——
所以别设计成合并，也别问「要覆盖还是只补缺失」；就一个语义，省得两头不讨好。

**DSH 界面「记忆」页**：标题行的「恢复…」→ 列出 `backupDir` 里的备份（戳/时间/条数/说明/大小）
→ 点「用这一份」。走的是 `POST /tag-memory-api/restore`，四步：

```
① 先验那一份还能不能读（CSV 解析得开、表头有 id 列），并把内容读进内存
   ——必须先读下来，后面「留档」还会往同一个目录写，现场读会被自己盖掉
② 强制先留档当前这一版（label = 「恢复 X 之前自动留档」）。留档失败 → 中止，一个字节都不动
③ 把内存里那份写回库里的 memory.csv 与 index.md（tmp + rename 原子替换，全程持写锁）
   —— backup.json 不还原：它装的是「备份地址/水位」这类设置，不是记忆内容
④ 换完复核记录数；对不上就报错，并告诉你用刚留的那一份回退
```

**手工恢复**（没有界面时）：

```
① 确认库目录（`<DSH_HOME>/tag-memory`）里 store/ 的现状（缺什么、坏什么）
② 从备份目录挑最近一份完整的三件套；先核 last-backup.log 里的条目数
③ 复制回 store/，文件名改回原名（去掉戳）
④ 验：memory.csv 能正确解析、条目数与备份时的数一致、index.md 的索引行与库条目对得上
```

**不管走哪条路，恢复前先把手上的 store/ 另存一份**——万一恢复的版本比现存的还旧，还能退回来。
界面那条路已经把这一步做成了强制步骤。

## 五之二、合并另一份记忆库

把别处（另一台机器、另一个引擎）的 `memory.csv` 并进来。规矩见 `portability.md` 第六节，
一句话：**先留档、只追加、不重写、不删任何条目、id 撞号按内容判**。

- 界面：「记忆」页标题行的「合并…」→ 填那份 CSV 的绝对路径 → **先预演**（不落笔）→ 看报告 → 「确认合并」。
- 预演就出一份交代：新增几条、重复跳过几条、撞号改新号几条、内容为空几条、**内容一样但标签不一样几条**。
- 内容一样但标签不一样：**不删**，按标签区分，报告里列出来让人自己决定要不要手改。

## 六、换机器时（重要）

`backupDir` 记的是**那台机器上的路径**，换机器后通常不存在。所以：

- **把插件装到新机器后，第一件事是检查 `backupDir`**——多半要为这台机器**重新设一个**。
- 别默默留着旧路径：备份会失败或写到错地方。
- **别和别的库共用一个备份目录**：轮转（留最近 `keepCopies` 份）是按目录数的，两套库共享会互相删。

**注意**：`backupDir` 记的是绝对路径，插件本身不存备份。如果当初把 `backupDir` 设在了插件目录里，
它会跟着插件一起被拷走，**旧机器的备份文件也在里面**——
留着无害（当历史留底），但**别误当成本机备份**。本机的备份看 `lastBackupAt`。
（库本身不在插件目录里，在 `<DSH_HOME>/tag-memory`，所以升级重装不会动它。）

## 七、备份之外的一层保险

**推荐做法**（因为发布包已不带 `store/`，覆盖解压本身已经安全）：

```
① 解压新版本，直接覆盖到原插件目录
② 库在 `<DSH_HOME>/tag-memory`、不在包里 → 原记忆文件原封不动 ← 用户这招的价值
③ 验：读一下库里的 memory.csv 条数没变
```

**要更保险时**（改结构、包里意外带了 store/、或用户特别交代）：

```
① 先备份（第三节）
② 把旧插件目录整体改名留底（例 dsh-tag-memory.bak-20261009）
③ 再解压新版本
④ 把旧库（`<DSH_HOME>/tag-memory/store/`）里的 index.md 与 memory.csv 拷回库目录
⑤ 验一遍（第五节）
```

详见 `storage-init.md` 第四节。
