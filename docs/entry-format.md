# 条目格式（CSV 列怎么填）

## 一、表头（固定，不要改顺序）

```
id,内容,时间,环境,原因,备注,稳定性,成熟度,距离,角色,项目,状态,关键词,工具,版本,依据,类型
└────── 前 6 列固定 ──────┘└─ 维度 ─┘└── 辅助标签，可增改 ──┘└主开关┘
```

**前 6 列固定**（规则）；**四个维度**是核心分类；**第 10 列起是辅助标签**。
**共 17 列**（2026-10-15 末尾新增 `类型`，主开关）。

> **⚠️ 迁移中**：`类型` 列已于 **2026-10-15** 加在表头末尾，存量行**一律回填 `记忆`**
> ——它们本来就是「从对话里提炼的结论」，正是 `记忆` 的定义；`固定` / `原文` 留给整理时逐条挑。
> **`成熟度` 改名 `深度`** 仍未做（见 `architecture.md` §七）——**所以第 8 列 `成熟度` = 字典里的 `深度`**。

---

## 二、逐列说明

| # | 列 | 必填 | 怎么填 |
|---|---|---|---|
| 1 | `id` | ✓ | `M-YYYYMMDD-NNN`，当天顺序号。**永不复用** |
| 2 | `内容` | ✓ | 一句话结论。**可多行** |
| 3 | `时间` | ✓ | 这条**什么时候发生的**，`YYYY-MM-DD` |
| 4 | `环境` | ✓ | **什么条件下成立**。写不清就别记 |
| 5 | `原因` | ✓ | 为什么记它 / 为什么成立 |
| 6 | `备注` | | 特殊情况、来源、限制 |
| 7 | `稳定性` | ✓ | **稳定 / 观察 / 易变**（没意外会不会变：不会→`稳定`；拿不准→`观察`；会变→`易变`）|
| 8 | `成熟度`〔= 字典的 **`深度`**〕| 视情况 | **情景 / 语义 / 程序**；**仅 `类型=记忆` 时填**，`类型=原文 / 固定` 时留空 |
| 9 | `距离` | ✓ | **常驻 / 按需 / 深藏**（召回优先级）|
| 10 | `角色` | 建议 | **谁写入的**（工作环境标识）：智能体名；多设备时 `名@机器` |
| 11 | `项目` | 建议 | 通用 / 项目名 |
| 12 | `状态` | ✓ | 生效 / 被取代 / 已归档 |
| 13 | `关键词` | | 自由填，逗号分隔。**兜底检索** |
| 14 | `工具` | | python / git / dsh / nowen-note … |
| 15 | `版本` | | v1 / v2 …。**冲突时区分两条都对的记忆**（当前全空是对的，见 `tags.md`） |
| 16 | `依据` | ✓ | **这话是谁说的**：`原话`（主子亲口）/ `推断`（萧潇归纳实测）/ `外部`（抄来的） |

**不填的列留空。**

> **`类型`（主开关：原文 / 记忆 / 固定）**：新维度，**表头迁移后才是独立一列**（见 §一）。
> 迁移完成前先在心里判：本机硬信息（python 装哪、哪个文件在哪）→ `固定`；直接存的原话原文 → `原文`；其余提炼结论 → `记忆`。

**⚠️ `角色` 与 `依据` 别混**（2026-10-12 新增 `依据`）：

| 列 | 回答 | 例 |
|---|---|---|
| `角色` | **谁写入的**（哪台机器、哪个智能体） | `萧潇` / `萧潇@工作机` |
| `依据` | **这话是谁说的** | `原话` / `推断` / `外部` |

**为什么加 `依据`**：库里 131 条无法区分「主子亲口说的」和「萧潇自己推的」——
主子的偏好、底线（`原话`）和我的归纳（`推断`）混在一起，**召回时被同等对待**。
详见 `tags.md` 第五节。

## 三、四个维度怎么判

| 维度 | 判据 | 举例 |
|---|---|---|
| `类型` | **原文 / 提炼结论 / 本机硬信息？** | 直接存原话 → `原文`；提炼的结论 → `记忆`；「python 装在 D 盘」→ `固定` |
| `深度` | **事件 / 规律 / 做法？**（仅 `类型=记忆`）| 「周二部署失败」→ `情景`；「部署前要查配置」→ `语义`；「部署三步走」→ `程序` |
| `稳定性` | **没意外会不会变？** | 「部署前查配置漂移」→ `稳定`；「这个做法还没验证过」→ `观察`；「服务器端口 8080」→ `易变` |
| `距离` | **召回优先级：多久用一次？** | 每轮都该在 → `常驻`；项目里常用 → `按需`；基本不用 → `深藏` |

**⚠️ `深度` 只在 `类型=记忆` 时填**；`类型=原文 / 固定` 时第 8 列**留空**。
（原先的「`稳定性=固定` 不打成熟度」，随 `类型` 引入已改为**按 `类型` 判**。）

## 四、CSV 写法规则（重要）

**内容里有逗号、引号、换行时，必须用双引号包裹整个单元格**：

```csv
M-20261010-001,"[通用] 示例
第二行说明",2026-10-10,"需要 XX 时","因为 YY","来源：ZZ",稳定,语义,常驻,本智能体,通用,生效,"a,b,c",python,
```

| 情况 | 写法 |
|---|---|
| 含逗号 | `"含,逗号"` |
| 含引号 | `"他说""你好"""`（引号双写） |
| 含换行 | `"第一行\n第二行"`（整格包引号） |

**写入方式**：用插件自带的 `memory_write` 工具（见 `workflow.md`），**不要手写 CSV**——手写极易破坏转义。

## 五、标题写法

```
[PrivHub] 前端用三栏布局
[通用] shell 命令里路径用正斜杠
[通用] python 装在 D:\Program Files
```

- 项目名取**用户认得的短名**，跟 `项目` 列一致
- 一句话说清「是什么」，不要写成问句

## 六、写入：先判路由，再过四原则

### 6.1 写入路由（先判这条输入是哪一类）

用户每说一句，先判**这一句属于哪一类输入**，再决定**写几条、写成什么形态**。
判据给模型用——**不要在程序里分类用户输入**（用正则/关键词猜必崩，换一种说法就漏）。

| 这一类 | 判据 | 写几条 | 写成什么 |
|---|---|---|---|
| **决策** | 我给了建议/选项，用户做了选择、或给出总方向 | 2 | ① `类型=原文`：`内容`＝问题＋我给的可选项＋用户的选择，`原因`＝为什么问。② `类型=记忆`、`深度=情景`：把结论提炼成一条 |
| **交代** | 用户主动说明背景、提建议 | 2 | ① `类型=原文`：原话照抄，`原因` 写前因、`环境` 写适用条件。② `类型=记忆`、`深度=语义` |
| **规矩** | 用户定长期禁令 / 硬边界（「以后都…」「不要再…」） | 2 | ① `类型=原文`：原话照抄。② `类型=记忆`、`深度=程序`、`距离=常驻`、`稳定性=稳定`、`依据=原话`——**它跟「交代」是一类话，但落库姿势不同：这条要常驻**，否则下次照样犯 |
| **纠正** | 用户说「不对，应该是…」 | 改 1 条 + 新 1 条 | 旧条 `状态=被取代`（**不删**）；新条 `依据=原话`、`备注` 写 `取代：M-xxxx` |
| **同意 / 确认** | 「好的」「可以」「就这个」 | 0 | 不新建条目；但若用户批准的是某个**做法**，把那条 `稳定性` 由 `观察` 升 `稳定` |
| **无复用价值** | 闲聊、临时进度、一次性中间结果 | 0 | 不记 |

**`原文` 条一律这么落**：`距离=深藏`、`稳定性=稳定`、`依据=原话`、`深度` 留白；
`备注` 写 `配套：M-xxxx`，指向同一次输入的总结条。
**同一次输入的 `原文` 条与总结条，冲突时以 `原文` 为准**——整理记忆库时同样按这个优先级。

> **原文为什么走 `距离=深藏`**：原文和总结是同一件事的两份记录，都进常规召回会互相抢，
> 库里条数还翻倍。让原文沉下去，需要它的时候（整理、追原话）再按 `类型=原文` 捞。
> **凭什么说「没复用价值」**：说不清「以后什么时候会用上」就不记——跟 `环境` 必填是同一把尺子。

### 6.2 写入四原则
1. **环境写清**——这条在什么条件下成立？写不清就先别记
2. **只记正向结论**——失败与问题**只记最终正确的做法**
   - ✓「shell 命令里路径用正斜杠」
   - ✗「不能用反斜杠」（错误形态会污染记忆）
   - **非断言不晋升**：「如果…就…」「假设…」「据说…」「打算…」「要不要…」**都不是结论**，不许当结论记
     - 要么**不记**；要么记成 `深度=情景`，并在 `内容` 里**明写是设想**
     - 判据：**这条是已经发生的，还是我在猜的？** 猜的 → 按设想记，不许进 `语义`/`程序`
     - 为什么单列：第 2 条管的是**错误形态**（不记「XX 不行」），**不管假设 / 引用 / 未来**——是两个漏洞
3. 成功经验、用户的要求 → 直接记，不必绕弯
4. 不记临时进度、一次性中间结果、别处抄来的内容

## 七、常见错误

| ✗ 错 | ✓ 对 | 为什么 |
|---|---|---|
| 内容含逗号但没包引号 | `"含,逗号"` | CSV 会错列 |
| 手写 CSV | 用 memory_write 工具追加 | 转义易错 |
| `类型≠记忆` 还填 `深度` | 留空 | 原文/固定不走形态分层 |
| 一条塞三件事 | 拆成三条 | 一条一个结论才好召回 |
| `环境` 写成「任何时候」 | 写具体条件 | 等于没写 |
| 记「XX 不行」 | 记「XX 应该怎么做」 | 错误形态污染记忆 |
| 把「如果…就…」当结论记 | 不记；或记成 `情景` 并标「设想」 | 假设、引用、未来都不是结论 |
| 直接改旧条目内容 | 加新条目 + 旧的改 `状态` | 保留演进痕迹 |
| 固定规则也凑满标签 | `类型=固定` 就够 | 多打是噪音 |
| 情景与语义混着写 | 事件归情景，规律归语义 | 混了就丢了升格入口 |

## 八、新增标签列怎么办

1. 在 CSV 表头**末尾追加**列名（**不要插在中间**——会错列）
2. 已有行该列**留空**——**例外是主开关类**（如 `类型`）：留白=黑名单，一按该列筛就把老条目全筛没了，**必须回填**
3. **同时登记进 `docs/tags.md`**，写清含义与调用时机

**改列名**：可以，但要**同步改所有引用它的文档**。
