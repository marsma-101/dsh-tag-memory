# 记忆机制总览

> 本文把三样东西缝在一起：**用户的三层架构**（外层）、**CoALA 四类**（经验沉淀内部）、**记忆工程机制**（升降级、遗忘、冲突消解）。
> 落地细则见 `workflow.md`、`charter.md`、`entry-format.md`；本文讲的是**为什么这样设计**。

---

## 一、三层总览（用户的架构）

```
┌─────────────────────────────────────────────────────────┐
│ ① 短期会话    不落盘（= 上下文窗口）                       │
│                说到值得留的 → 自动打标入库                │
├─────────────────────────────────────────────────────────┤
│ ② 提炼结论    ← `类型=记忆`，内部含 CoALA 四层，【有升降级】│
│                工作 / 情景 / 语义 / 程序                  │
├─────────────────────────────────────────────────────────┤
│ ③ 本机硬信息  ← `类型=固定`，【无升降级】                  │
│                文件在哪、装在哪、物理规律、固定用法         │
└─────────────────────────────────────────────────────────┘
```

> 另有一路 `类型=原文`：**原话原文直接留存**，不加工、不走形态分层。

**存储是平级的**：一个库，所有条目同级。分层靠**标签**，不靠文件夹——所以改层级＝改标签，不用挪条目。

**各自的 `类型` 与分工**：

| 层 | `类型` | 装什么 | 会变吗 | 升降级 |
|---|---|---|---|---|
| 短期会话 | 不落盘 | 当前任务、当轮对话 | 每轮变 | 不适用 |
| 原文 | `原文` | 直接留存的原话/原文，不加工 | — | 无 |
| 经验沉淀 | `记忆` | 经过、判断原则、项目说明文件何时该读 | 会 | **有** |
| 固定规则 | `固定` | 文件位置、环境事实、普遍规律 | 基本不变 | 无 |

## 二、经验沉淀内部：CoALA 四层

来源：CoALA 框架（Sumers 等，普林斯顿，2023，[arXiv:2309.02427](https://arxiv.org/abs/2309.02427)）。

**四类不是四个并列的层，落到两类标签**：情景 / 语义 / 程序 = `深度`；工作 = `距离`（进不进上下文）。

| 类型 | 装什么 | 存活 | 例子 |
|---|---|---|---|
| **工作** | 当前活跃内容 | 一次推理 | 这轮对话、手头任务 |
| **情景** | 绑定时刻的具体事件 | 天 / 周 | 「周二那笔部署失败了，因为配置漂移」 |
| **语义** | 从若干情景抽出的一般知识 | 持久 | 「部署前先查配置漂移」 |
| **程序** | 怎么做一件事 | 最稳 | 「遇到这类告警，先查连接池」 |

**关键分界线在情景与语义之间**：

> 一条情景是「2 月 14 日那笔交易栽在财报上」。
> 一条语义是「财报前波动率会上升，进场要更谨慎」。
> **前者是事件，后者是从许多事件里抽出来的教训。**
> 只存情景的智能体，什么都记得，什么都不理解。

**工作记忆不落盘**——它就是上下文窗口本身，其它三层都必须被检索进工作记忆才能影响输出。

## 三、六阶段生命周期

**每一段长期记忆（情景/语义/程序）都走同一条路：**

```
提取 → 存储 → 检索 → 注入 → 更新 → 遗忘
```

| 阶段 | 做什么 | 本插件的对应 |
|---|---|---|
| **提取** | 判断哪部分值得记住 | 「动库时机」+ 写入四原则 |
| **存储** | 写到持久处 | 追加进 `memory.csv` |
| **检索** | 取回**真正相关**的，不是最近的 | 召回漏斗（标签筛） |
| **注入** | 格式化成能用的形式 | 读出正文四要素 |
| **更新** | 修订（巩固、取代） | 第五节、第六节 |
| **遗忘** | 降权、归档 | 第七节 |

**「检索错记忆往往比不检索更糟」**——这是漏斗要严格的原因。

## 四、升：巩固（consolidation）

**「升」发生在「更新」阶段，机制叫巩固。**

```
情景（具体事件）
   ↓ ① 聚类：相似事件归一堆
   ↓ ② 门槛：这一堆必须够多（参考值 ≥3 个独立场合）
   ↓ ③ 提炼：概括成一条带条件的规则
   ↓ ④ 携带：支撑数 + 适用条件 + 观察时间跨度
语义（一般规律）
   ↓ 再巩固
程序（技能/做法）
```

**核心一句**：

> **一个案例不是规律，是噪声。**

支撑数不够就**不许升格**。从单个事件推出来的规则，是在对噪声过拟合。

**本插件怎么落**：

- 情景 → 语义：同类经验出现在 **≥3 个独立场合**，可提炼成一条「规律」条目
- 语义 → 程序：该规律在**多个不同场景**反复验证，可提炼成「做法」
- 升格时**带上支撑证据**（哪几条情景支撑了它、各是哪一次），写在 `备注` 里
- **升格是判断动作，不是自动动作**——先问用户

**⚠️ 数的是「独立场合」，不是「条数」**：

| 情形 | 算几个场合 |
|---|---|
| **不同说话人** | 各算一个 |
| **同一人在不同会话 / 不同时间** | 各算一个 |
| **同一个人在一次对话里说多次** | **只算一个** |

数条数会把「有人一口气说了两遍」看成两个见证人——要的是**两个人，或同一个人在两个不同场合**。
所以升级时要在 `备注` 里写明**每个场合是哪一次**，否则数不清也复核不了。

## 五、降：可及性衰减（不是删除）

**「降」发生在「遗忘」阶段。**

> **遗忘不是记忆的缺陷，是它的功能。**

**核心区分**：

> **有设计的遗忘管的是「可及性」，不是「销毁」。**

| 手段 | 说明 |
|---|---|
| **时间衰减** | 越老权重越轻（指数曲线） |
| **重要性加权** | 关键的比日常的留得久 |
| **间隔强化** | 被用过就抬回来 |
| **预算淘汰** | 超预算淘汰价值最低的 → **进冷存档** |

**本插件怎么落**：

- 降级 ≠ 删除。把 `状态` 改成 `已归档`，**原文保留**。
- 检索默认过滤 `已归档`，但**查得到**（回答「那个方案后来怎样了」）。
- **不做自动衰减**（本插件无后台进程）。衰减靠**人工复核**：定期看哪些条目不常用了。
- 被反复用到的条目 → 把 `距离` 提到 `常驻`（或 `项目` 填 `通用`）。

## 六、冲突消解（治「过期」的核心）

**问题**：事实变了，旧记录还在，检索时两条都返回，没有裁决。

**这叫「冲突盲区」**。没有主动消解，陈旧事实会堆积、污染推理。

### 关键原则

> **更新的不一定更真。** 冲突消解**不是**自动挑更新的那条。

```
新记忆与旧记忆冲突时：
  ① 比来源可靠度 + 新鲜度 + 与其余知识的一致性
  ② 谁更可靠谁赢
  ③ 旧的【降权】，不是当场抹掉          ← 关键
  ④ 新的在 `备注` 里写「取代：旧id」     ← 留溯源
```

**为什么降权而不是删除**：如果新证据后来被证伪，**旧的还能恢复**。

### 三种「过期」要分清

| 类型 | 本质 | 怎么认 | 怎么处理 |
|---|---|---|---|
| **作用域错配** | 横向：本来就不是这里的 | 记忆标的项目 ≠ 当前 | **不是过期**；先问一句 |
| **被取代** | 纵向：同一问题换了决定 | 有明确的新决定 | 旧的标 `被取代`，留溯源 |
| **静默失效** | 外部变了，没人说 | **内部发现不了** | 涉及易变对象，**用前先核对** |

### 本插件怎么落

1. `状态` 用三态：`生效` / `被取代` / `已归档`
2. 新条目在 `备注` 里写「取代：M-xxxx」
3. 检索默认过滤 `被取代`，但**留得下来**可查
4. **权威文档优先于记忆条目**——型态文件在，就压过累积记忆
5. **显式引用**：依据记忆做决定时，说出依据的是哪一条（`M-xxxx`）→ 冲突自己浮出来

> **「记忆隐式影响判断 → 冲突不可见；记忆被显式引用 → 冲突自己浮出来。」**

## 七、`类型=固定`（本机硬信息，不在四层内）

**判据：本机/外部的硬信息——「在哪、装在哪」这一类。**

| 类 | 例 | 存不存 |
|---|---|---|
| 位置类 | 文件在哪、python 装在哪、说明书在哪 | **必须存**（主力） |
| 环境类 | 这台机器的路径、端口、约定 | 必须存 |
| 普遍规律 | 物理/数学规则、固定用法 | 可存（模型自定） |

**与「钉住」的区别**（别混）：

| | 固定规则 | 钉住（四层内） |
|---|---|---|
| 性质 | **客观**：位置、规律 | **主观**：用户的偏好、底线 |
| 依据 | 可核实 | 用户说了算 |
| 归属 | 外层，独立 | 四层里的作用域 |

**固定规则无升降级**——它要么成立，要么不成立。

**指向性优于内容性**（抗过期最有效的一招）：

| | 记内容 | 记指针 |
|---|---|---|
| 写法 | 「v1 架构是三栏布局」 | 「做架构决定前先看 v1 型态文件（路径）」 |
| v2 来了 | 几十条全变废 | **改一行** |

## 八、标签映射表（已演进为 `类型` + 三个维度）

> ⚠️ **本节已更新（2026-10-13）**：原「层/类型/时效」三套标签，**已合并为 `类型` + 三个维度**。
> 合并理由与各家架构对比见 `three-axes.md`；总纲见 `architecture.md`；完整字典见 `tags.md`。

| 维度 | 取值 | 管什么 | 合并自 |
|---|---|---|---|
| `类型` | 原文 / 记忆 / 固定 | **主开关** | 新增（原文层 / 经验沉淀 / 固定规则）|
| `深度` | 情景 / 语义 / 程序 | **能不能当规律用** | CoALA 四层（形态三层）|
| `稳定性` | 稳定 / 观察 / 易变 | **该不该核对** | 用户「三层」+ 旧「时效」 |
| `距离` | 常驻 / 按需 / 深藏 | **要不要进上下文** | mnemon 三层到达 + auto-memory 详细度 |

**辅助标签**：`角色` / `依据` / `项目` / `状态` / `关键词` / `工具` / `版本`
（meow 的「关于谁」并入 `角色`/`项目`；mneme 的「还有效吗」并入 `状态`）

**按需打标签**：打够将来真能检索到就行，**多打是噪音**。
`类型=固定` 的条目可**不打** `角色`——没人会按「哪个智能体存的」去查物理规律。

### `稳定性` 怎么用

| 取值 | 含义 | 遇到时怎么做 |
|---|---|---|
| **稳定** | 不会变 | **直接用** |
| **观察** | 还没定 / 拿不准 | **简单判断一下**再用 |
| **易变** | 会变 | **着重考虑**这条在这里还成不成立 |

## 九、落地检查清单

写一条记忆前，自问：

```
□ 类型？          原文（直接存原话）/ 记忆（提炼结论）/ 固定（本机硬信息）
□ 深度？          事件→情景；规律→语义；做法→程序（仅 `类型=记忆`）
□ 稳定性？        没意外会不会变 → 稳定 / 观察 / 易变
□ 距离？          召回优先级 → 常驻 / 按需 / 深藏
□ 环境写清了吗？   什么条件下成立
□ 只记正向结论了吗？ 失败只记「最终正确的做法」
□ 有没有跟已有条目冲突？ 有 → 走 conflict.md
□ 该打哪些标签？   最小充分，不多打
```

检索到一条旧记忆时，自问：

```
□ 它的 稳定性 是什么？
   稳定 → 直接用
   观察 → 简单核对
   易变 → 先核对当前情况
□ 它被取代过吗？        状态 是 `被取代` 吗
□ 有权威文档吗？        有 → 以文档为准
```
