# 三种架构（差异化对照）

> 规则的原则：
> **各家架构不能照单全收**——**分类规则和升降级规则相同或相近的，必须合并**。
> 否则「召回时几个轴筛出来的东西总是一样的」，多写一套解释就白写了。
>
> 本文先摆各家原始架构，再说明**为什么合并成这几个维度**，以及**各维度的差异在哪**。
>
> **更新（2026-10-13）**：在三个维度之前又加了主开关 **`类型`**（原文 / 记忆 / 固定），
> 且 `成熟度` 已改名 **`深度`**。**当前设计以 `architecture.md` 为准**；本文保留各家对照与合并理由。

---

## 一、各家架构原样（实测查证）

| 来源 | 轴 | 取值 | 分类依据 | 升降级机制 |
|---|---|---|---|---|
| **用户三层** | 稳定度 | 短期会话 / 经验沉淀 / 固定规则 | **会不会变** | 几乎不升；降=发现会变 |
| **CoALA 四层** | 认知类型 | 工作 / 情景 / 语义 / 程序 | **是什么东西** | **情景→语义→程序**（够独立场合数才升） |
| **dsh-mnemon** | 到达方式 | Runtime / Documents / Memory Spaces | **怎么到达模型** | 换 Strategy，**不搬数据** |
| **dsh-meow-memory** | 关于谁 | soul / user / project / fact / lesson / topic / rules | **关于谁** | 强化 +0.3；多项目验证→晋升 |
| **dsh-auto-memory** | 详细度 | 目录 / 摘要 / 原文 | **多详细** | 按需逐层下降 |
| **dsh-mneme** | 生命周期 | active / archived / superseded | **还有效吗** | keep/merge/archive/supersede |

## 二、哪些该合并（逐对比较）

**判据**：**分类依据相同 或 升降级机制相同 → 合并。**

| 对比 | 分类依据 | 升降机制 | 结论 |
|---|---|---|---|
| 用户三层 ↔ 时效（旧） | **都是「会不会变」** | 都是「几乎不升降」 | **合并** → 稳定性轴 |
| mnemon ↔ auto-memory | 都是「**怎么到达模型**」 | 都是「按需逐层」 | **合并** → 距离轴 |
| CoALA ↔ 新 `类型` | **不是一回事** | CoALA 有升格链；`类型` 不升降 | **拆开**：CoALA 形态 = `深度`；`类型` 是另一根**主开关**（原文/记忆/固定）|
| meow 七层（soul/user/project） | 「**关于谁**」 | 无独立升降 | **并入** `角色`/`项目` 标签，**不单独成轴** |
| mneme 生命周期 | 「**还有效吗**」 | supersede/archive | **并入** `状态` 标签，**不单独成轴** |

## 三、最终：`类型` + 三个维度

### 轴零：`类型` —— 这是什么（**主开关**）

| 取值 | 含义 |
|---|---|
| `原文` | **原话原文直接留存**，不加工、不走形态分层 |
| `记忆` | **从对话里提炼的结论**（常态）|
| `固定` | **本机/外部硬信息**：文件在哪、装在哪、普遍规律 |

**激活规则**：`类型=记忆` 才启用 `深度`；`原文 / 固定` 时 `深度` 留白。

---

### 轴一：`稳定性` —— 会不会变

| 取值 | 含义 | 对应各家 |
|---|---|---|
| `稳定` | **不会变**：客观事实、成熟做法 | 用户三层「固定规则」+ 时效「稳定」 |
| `观察` | **还没定 / 拿不准**：待验证的做法 | ——（新增）|
| `易变` | **会变**：版本相关、临时状态、地址端口 | 时效「易变」 |

**升降规则**：**几乎不升**。降 = **发现它会变**（`稳定`→`观察`→`易变`）。
**它回答的问题**：**这条该不该核对？**

---

### 轴二：`深度` —— 想清楚没有

| 取值 | 含义 | 对应 CoALA |
|---|---|---|
| `情景` | **具体事件**：某天发生了什么 | episodic |
| `语义` | **一般规律**：从若干情景抽出来的 | semantic |
| `程序` | **做法**：怎么执行一件事 | procedural |

**升降规则**：**有明确升格链**——`情景` →（同类 ≥3 个**独立场合**）→ `语义` →（多场景验证）→ `程序`。
**它回答的问题**：**这条能不能当规律用？**

---

### 轴三：`距离` —— 召回优先级（多久用一次）

| 取值 | 含义 | 对应各家 |
|---|---|---|
| `常驻` | **每轮进上下文** | mnemon Runtime / auto-memory 目录层 |
| `按需` | **相关时才读** | mnemon Documents / Memory Spaces |
| `深藏` | **基本不读，查历史才看** | auto-memory 原文层 / mneme archived |

**升降规则**：**按调用频率调**——常用的提到 `常驻`，久不用的降到 `深藏`。
**它回答的问题**：**要不要进上下文？**

---

## 四、⭐ 各维度的差异在哪（为什么不会筛出一样的东西）

设计时要注意的是：**「召回的东西总是一样，多写一套就白写了」**。

**各维度正交，筛出来的集合确实不同**：

| 用哪个维度筛 | 拿到什么 | 典型场景 |
|---|---|---|
| **类型** | 「**原文**」 vs 「**结论**」 vs 「**本机硬信息**」 | 只要原话 → 筛 `原文`；要可执行事实 → 筛 `固定` |
| **稳定性** | 「**可信的**」 vs 「**要核对的**」 | 要照做之前 → 先筛 `稳定`+`观察` |
| **深度** | 「**事件**」 vs 「**规律**」 vs 「**做法**」 | 要定方案 → 筛 `语义`；要执行 → 筛 `程序` |
| **距离** | 「**该进的**」 vs 「**要查的**」 | 每轮装配 → 只取 `常驻` |

**各维度的升降规则也完全不同**：

| 维度 | 怎么升 | 怎么降 | 谁在动 |
|---|---|---|---|
| **类型** | 不升降（写时定）| —— | —— |
| **稳定性** | **几乎不升** | 发现会变 → 降级 | **环境**在动（世界变了） |
| **深度** | **有升格链**，够**独立场合数**才升 | 很少降 | **认识**在动（想明白了） |
| **距离** | 常用 → 提到常驻 | 久不用 → 降到深藏 | **使用**在动（用得多不多） |

**一句话区分**：
- **类型** 管 **「是不是原文」**
- **稳定性** 管 **「信不信」**
- **深度** 管 **「是不是规律」**
- **距离** 管 **「读不读」**

## 五、举例：一条记忆的各维值

```
M-001  [PrivHub] v1 架构用三栏布局
  类型=记忆      ← 提炼过的一条结论
  深度=情景      ← 是"v1 当时的决定"这个事件
  稳定性=稳定    ← 这个事实不会变
  距离=按需      ← 只在讨论 v1 时读
  角色=萧潇  项目=PrivHub  版本=v1  状态=生效
```

```
M-002  [通用] 部署前先查配置漂移
  类型=记忆      ← 提炼过的结论
  深度=语义      ← 是从多次部署教训里抽出来的规律
  稳定性=稳定    ← 这个原则基本不变
  距离=常驻      ← 常用，每轮都该在
  角色=萧潇  项目=通用  状态=生效
```

```
M-003  [通用] python 装在 D:\Program Files\Python312
  类型=固定      ← 本机硬信息
  （深度留白）    ← 非记忆类型，不走形态分层
  距离=按需
  状态=生效
```

**同一个项目下的两条记忆，各维的值都不同**——**筛「深度=语义」和筛「类型=固定」拿到的是完全不同的集合**。

## 六、为什么不用「七层」

用户之前说的「七层」，其实是 **`类型` + 三个维度**叠起来的：

```
⑦ 短期会话    ← 不是标签，是上下文本身
⑥ memory 入口  ← 不是标签，是文件
⑤ 工作记忆    ← `距离`（进不进上下文）
④ 情景记忆    ← `深度`=情景
③ 语义记忆    ← `深度`=语义
② 程序记忆    ← `深度`=程序
① 固定规则    ← `类型`=固定
```

**七层里混了三种不同的东西**：会话、文件、记忆类型。
**拆开之后，每个维度只回答一个问题**，筛起来才准。

**这也正好实现用户要的「不超过三种」。**

## 七、对比各家：咱们这样做的优势

| | 他们 | 咱们 |
|---|---|---|
| 维度数 | 各家 3-7 层不等 | **统一 `类型` + 三个维度** |
| 换层级 | 迁表 / 改文件 / 换 Strategy | **改标签值** |
| 维度的性质 | 有的混在一起（如 meow 七层混了"关于谁"和"是什么"） | **每维只回答一个问题** |
| 加新维度 | 要改代码 | **加一个标签列** |
| 召回 | 靠打分排序 | **靠标签筛 + 打分** |

**关键差异**：**他们的层级是「结构」，咱们的维度是「标签值」**。
结构改起来要迁移，标签改起来就是改个字段。
