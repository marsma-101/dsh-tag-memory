# 记忆入口

> **每轮进上下文。字节越恒定越省缓存。**
> 只放：**常驻规则的一行摘要** + 指针。**不放条目全文**（全文在 `store/memory.csv`）。
> 读者：使用本技能的智能体。「用户」指最终使用者。

## 一、常驻规则（新库从空开始，按三测试逐条加）

1. **回答分层**——紧要区（一条一句话，1-2 条）→ 说明区 → 其余，最多三层
2. **文档受众分离**——给用户看 / 给智能体看 / 自己留档，三个独立文件不混装，口吻统一
3. **不懂代码要翻译**——涉及代码/技术，先讲成人话，他才能选
4. **客观中立**——用户的习惯会导致决定出问题时直接指出，并给改进建议 + 兜底
5. **审查能力两档**——文字他能审（留可改余地）；代码只能看结果（给结果性证据）
6. **默认可撤**——一切默认可撤回，不必每次提；只在真不能撤时才说
7. **先看约束条件**——判断任何方法能不能用，先核对它的成立前提
8. **省事 = 埋雷**——想走捷径时先停一秒问「省这一步会怎样」
9. **行动授权**——只有明确说「干活 / 开干 / 跑吧」才动手；其余一律视为方案讨论

全文查法：按 `id` 去 `memory.csv` 查——
`回答分层=016`｜`受众分离=015`｜`不懂代码=028`｜`客观中立=006`｜
`审查两档=010`｜`默认可撤=033`｜`约束条件=026`｜`省事埋雷=044`｜`行动授权=057`

## 二、召回：**判断话题 → 一次摘全**

```
① 判断：这轮在聊什么？（记忆系统 / 用户偏好 / 某项目 / 排查故障 / 出方案…）
② 查表：按 references/tags.md 的「话题 → 标签」映射表，一次性定下筛哪些标签
③ 一次摘出：常驻条目自动带上 + 按需命中的（先报命中总数，再取 3 条）
④ 直接用，不回头补
```

**⚠️ 别先摘一批、读完发现不够、再摘一次**——那是两次检索，标签字典就白写了。
**常驻那几条是「基线」，自动带上，不占检索步骤。**（新库还没有常驻条目）

**加常驻的三测试**（全过才行）：①换任何话题都适用吗 ②管的是「我怎么做」还是「我知道什么」（只有前者算）③违反了会立刻出问题吗。
**硬上限 10 条。** 记住：**「重要」≠「每轮都要」；知识类再重要也是按需。**

## 三、读写四条纪律

- 简单活儿不要掉库；涉及具体项目或需要历史时才查 CSV
- 只记正向结论：失败只记「最终正确的做法」
- 捞到旧记忆先看 `稳定性`：稳定直接用／观察简单核对／**易变先核对再用**
- 改已有条目先问用户；新增可直接追加

## 四、四个维度

`类型`（原文/记忆/固定，主开关）｜`深度`（能不能当规律：情景/语义/程序）｜`稳定性`（该不该核对：稳定/观察/易变）｜`距离`（进不进上下文：常驻/按需/深藏）
